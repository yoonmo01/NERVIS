# NERVIS 프런트 화면 설계 초안

작성·갱신: 2026-10-21. **사용자가 동의한 중앙 NERVIS 타이틀→왼쪽 위 이동→푸른 다층 코어와 분석 전환을 첫 React·Three.js 화면으로 구현했다.** 실제 영역·단면·대응 파형 조회도 기존 FastAPI에 연결했다. 대화·음성 연결은 아직 없다. 아래의 확장 설계와 실제 구현 범위를 구분하며, 세부 배치·모션은 실행 화면에서 검토한다. 기준: [프로젝트 방향](PROJECT_DIRECTION.md), [시나리오](VIDEO_SCENARIO.md), [서버 구조](SYSTEM_ARCHITECTURE.md).

**최신 상태(2026-10-22):** 12절의 공통 입력창·로컬 자동 분석 무대를 구현했다. 7~11절은 이전 구현 이력이다. 8절의 오늘 브리핑·자연어 실행·실제 AI/음성·전체 요청 순차 처리는 후속 작업이다.

## 1. 이번에 확인할 디자인

아이언맨 작업실처럼 중앙 대상을 조작하는 무대를 중심으로, 좌우 비교와 파형·명령 콘솔이 떠 있는 화면을 제안한다. 사용자가 질문을 바꾸면 선택 대상·카메라·분석 패널이 함께 바뀌어야 한다. 개별 차트의 장식보다 실제 영역 선택과 관계 발견이 영상의 중심이다.

시안: [NERVIS interface concept v1](../reports/design/nervis-interface-concept-v1.png). 직접 생성한 디자인 검토용 이미지이며 reports 아래 로컬에 보관한다. 실제 뇌 자료·수치·개인 정보는 생성 도구에 보내지 않았다. 시안의 모든 해부학·파형·좌표는 가상이며, 실제 앱 화면이나 구현 성능의 증거가 아니다.

참고한 제작사 작업:

- [Perception — Iron Man 2](https://www.experienceperception.com/work/iron-man-2/): 중앙 대상을 중심으로 한 공간적 정보 배치와 전환.
- [Cantina Creative — Iron Man 3](https://www.cantinacreative.com/film/iron-man-3): 얇은 선·조준 표시·HUD 디테일과 모션.
- [Territory Studio — Avengers: Age of Ultron](https://creativepool.com/Territory/projects/avengers-age-of-ultron-ui-screen-graphics): 해부학 이미지·파형·연구용 패널의 결합.

시각 언어를 참고하며 영화의 로고·화면 캡처·음성·음악을 제품 자산으로 사용하지 않는다.

### 1.1 첫 화면: NERVIS 구형 코어

사용자가 첨부한 두 번째 황금색 구형 인터페이스를 **형태의 주 레퍼런스**로 사용한다. 겹친 궤도선·분절된 곡선과 패널·안쪽 구조·외곽 입자 등 여러 층이 있는 구형 코어로 구성한다. 첫 번째 레퍼런스는 푸른 입자와 빛의 분위기를 참고한다. 주 색상은 파랑·청록·차가운 흰색이며 주황색 레퍼런스의 색 자체를 채택하지 않는다. 단순한 점 구체 한 겹으로 축소하지 않고 깊이 있는 구조를 표현하되 실제 PC 성능에 맞춰 밀도를 조정한다. 캡처 이미지를 붙여 재생하지 않고 Three.js로 자체 구현한다.

시작 연출은 다음 순서다. 거의 검은 배경 중앙에 NERVIS 타이틀이 나타나고, 타이틀이 작아지며 왼쪽 위의 브랜드 위치로 이동한다. 같은 글자 요소가 이동해 화면의 연속성을 유지한다. 그다음 중앙에 코어의 안쪽 구조·궤도선·외곽 입자가 단계적으로 나타난다. 코어가 나타난 뒤에는 NERVIS 글자를 중앙에 중복 표시하지 않고 왼쪽 위에 유지한다. 완료 후 하단 입력·자막·실제 상태를 표시하고 코어가 대기 움직임을 시작한다. 움직임 축소 환경에서는 긴 이동·입자 전개를 짧은 전환으로 대체한다.

아직 분석을 요청하지 않은 상태에서 MRI와 모든 분석 패널을 펼쳐놓지 않는다. 코어는 시스템의 시각적 정체성이며 제공된 뇌나 소유자의 의식·인격을 재현한 것으로 설명하지 않는다.

| 실제 상태 | 코어 표현 | 상태를 바꾸는 근거 |
|---|---|---|
| 시작 연출 | 중앙 NERVIS 타이틀 → 왼쪽 위로 이동 → 중앙 코어 구성 | 앱 진입. 이 연출을 실제 서버 연결 완료·AI 호출 성공으로 표현하지 않음 |
| 대기 | 다층 코어의 느린 회전·약한 호흡·절제된 입자 | 입력 대기. NERVIS 이름은 왼쪽 위, 마이크 꺼짐을 구분 |
| 호출 후 활성 | 외곽선·입자 밀도가 잠시 또렷해짐 | 실제 활성화 동작. 초기에는 시작 버튼 |
| 듣기 | 입력 음량에 작은 외곽 반응, 듣기 표시 | 마이크 권한과 실제 녹음이 켜진 동안만 |
| 요청 처리 | 궤도선·입자가 안쪽으로 정돈됨 | 실제 요청 시작부터 성공/실패까지 |
| 말하기 | 음성의 강약에 따라 밝기·크기·외곽 입자 변화 | 실제 응답 오디오 재생과 음량 측정 |
| 오류·종료 | 움직임을 줄이고 짧은 상태 설명 | 실패·재생 중단·세션 종료 이벤트 |

발화 반응은 재생하는 음성을 Web Audio의 AnalyserNode 등으로 로컬 측정해 프레임 갱신에 연결한다. 시작·일시정지·종료·재생 실패에 맞춰 반응도 바뀌어야 한다. 임의 애니메이션을 실제 음성 분석 결과나 뇌 신호로 표시하지 않는다. 브라우저 오디오 활성화는 사용자의 시작 동작으로 처리한다.

뇌 분석을 요청하면 코어가 작아져 가장자리로 이동하고 중앙에 실제 단면·선택 영역과 분석 패널이 나타난다. 분석 화면에서 시스템이 응답할 때도 작은 코어가 음성에 반응한다. 홈으로 돌아가면 중앙 코어 구도로 복귀한다. 분석 중 선택·구간은 화면 전환만으로 초기화하지 않는다.

## 2. 시안과 실제 구현을 구분한다

- 시안의 매끈한 입체 뇌는 합성한 조형이다. 현재 단면으로 동일한 정밀 3D 구조를 복원할 수 있다고 가정하지 않는다.
- 실제 자료는 Axial·Coronal이다. 시안의 Sagittal 메뉴·해당 방향 썸네일은 제거한다. 미구현 Export 메뉴도 초기 구현에서 제외한다.
- 근거 없는 A/L/S 좌표는 제거한다. 실제로 제공되는 단면 번호와 이미지 픽셀 좌표만 필요할 때 표시한다.
- 밝기·강조는 실제 마스크·시계열과 연결하고 원래 영상 좌우를 임의로 뒤집지 않는다. 좌우 명칭은 데이터의 hemisphere로 판정한다.
- 가운데 입체 표현은 한 방향의 단면에 상대 깊이를 주는 방식을 먼저 검토한다. 별도 추상 뇌 실루엣을 쓰면 실제 해부학의 복원 결과와 구분한다. 실시간 성능과 실제 데이터 모양을 보고 최종 방식을 정한다.
- 시안의 파형은 시각 예시다. 구현에서는 API 응답의 원척도·z-score와 실제 상관을 표시한다. 상관을 백분율로 변환하지 않는다.
- 호출·듣기·계산·말하기 표시는 해당 기능의 실제 상태와 연결한다. 텍스트·버튼만 연결한 단계에서 음성 인식이 작동하는 것처럼 표시하지 않는다.

## 3. 화면 구성

| 영역 | 내용 | 동작 |
|---|---|---|
| 상단 | 시작 연출 후 왼쪽 위에 정착한 NERVIS, 현재 보기, 로컬 서버 상태 | 타이틀은 코어와 별개로 유지, API 확인 후 연결 상태 갱신 |
| 중앙 무대 | 홈은 NERVIS 코어, 분석은 실제 단면·마스크 | 홈/분석 전환, 선택·확대·단면 전환, 예술 모드로 연속 전환 |
| 좌우 비교 패널 | 선택 ROI의 위치·이름·반구·구조 지표 | 원래 위치를 남기고 확대, 대응 영역 조회 |
| 관계 패널 | 두 파형·상관·검색 결과·현재 조건 | 실제 계산 성공 후 결과 갱신 |
| 하단 시간 탐색 | sample 축, 선택 구간, 재생 커서·속도 | 그래프 커서와 영역 밝기 동기화. 구간과 커서는 분리 |
| 명령 콘솔 | 텍스트 입력·응답, 향후 마이크 상태 | 초기에는 직접 조작과 명시된 미리보기. 이후 실제 AI·음성으로 확장 |

배경은 #050B12 계열, 인터페이스 강조는 #66E3FF·차가운 흰색·소량의 #F5BC78 계열을 제안한다. 실제 ROI 색과 인터페이스 강조색은 역할을 분리한다. 동일한 영역은 장면이 달라도 같은 ID·이름·색으로 추적 가능해야 한다.

제작 기준은 16:9·1080p 녹화 구도다. 핵심 한국어와 수치는 영상에서 읽을 수 있는 크기로 두고, 세부 기술 장식은 정보의 위계를 가리지 않게 한다. 색 이외에 이름·선 스타일·선택 테두리도 사용하고 키보드 초점과 오류 메시지를 제공한다.

## 4. 다섯 가지 화면 상태

| 상태 | 핵심 화면 | 다음 변화 |
|---|---|---|
| 시작·대기·활성화 | 중앙 타이틀이 왼쪽 위로 이동한 뒤 중앙에 푸른 다층 코어, 하단 입력·실제 상태 | 코어 등장 후 대기, 호출·시작 후 활성, 분석 요청 시 코어 축소·단면과 패널 등장 |
| 탐색 | 중앙 단면과 선택 가능한 영역, 전체 파형 | 선택 영역의 위치·정보 연결 |
| 두 영역 비교 | 대응 위치와 두 확대 패널, 파형·구조 차이 | 비교 결과에 시선 집중 |
| 구간별 관계 | 같은 두 영역과 이동 창 그래프 | 구간 강조·재생에 맞춰 밝기와 커서 갱신 |
| 예술 표현 | 주변 패널을 줄이고 형태·빛·관계 강조 | 같은 선택과 구간을 유지해 데이터 장면과 연결 |

API 요청 중에는 로딩, 실패 시에는 오류와 재시도를 표시한다. 이전 결과를 남길 수 있지만 새 조건의 결과처럼 보여주지 않는다. 빠르게 선택을 바꿨을 때 늦게 도착한 이전 요청이 최신 화면을 덮어쓰지 않도록 한다. 실제 분석 완료와 카메라/패널 전환 완료를 구분한다.

## 5. 기술과 API 연결

- React·TypeScript·Vite: 화면·선택·분석 구간·재생·입력 상태.
- Three.js·React Three Fiber: 공간 배치·카메라·ROI 강조·빛/입자. 실제 성능을 측정하며 효과를 조정한다.
- Web Audio: 실제 재생 음성의 강약을 측정해 코어에 연결한다. 듣기와 말하기의 입력원을 구분하고 측정은 로컬에서 수행한다.
- 첫 두 파형은 SVG로 표시하며 같은 세로축을 공유한다. ECharts는 구간 탐색·이동 창·행렬 등 고급 조작을 추가할 때의 채택 계획이다. z-score는 API의 전체200점 기준을 유지한다.
- 기존 FastAPI: dataset/regions/slices로 초기 표시, timeseries/compare/pairs/windows로 분석 결과, 등록 PNG 경로로 실제 이미지 조회.
- Blender는 고급 조형·도입/전환 소재가 필요한 경우의 선택 도구다. 초기 실시간 화면의 필수 조건으로 두지 않는다.

API 키를 브라우저에 넣지 않는다. 실제 마스크·시계열은 로컬 API에서만 받으며 외부 생성 도구나 LLM으로 보내지 않는다. 단면·색상·수치를 이미지 시안에서 추출해서 실제 데이터처럼 사용하지 않는다.

## 6. 다음 순서와 검증

1. 분석 화면 v1과 홈 코어 중심 흐름은 사용자 동의 상태다. 타이틀 이동과 주황색 레퍼런스 형태의 푸른 코어를 최신 시작 화면 기준으로 삼는다.
2. 홈 화면 정지 시안이 필요하면 한 장으로 구도만 확인한다. 모든 상태의 이미지를 승인받아야만 구현하는 절차를 만들지 않는다. 정지 이미지는 움직임·성능의 증거가 아니다.
3. 구현 단계의 첫 결과물은 브라우저에서 실행되는 타이틀 이동·다층 코어 등장·대기 움직임과 분석 화면 전환이다. 초기 버튼·오디오 반응 테스트는 명시적으로 미리보기로 표시하고 실제 AI·STT·TTS 연결로 소개하지 않는다. 실제 뇌 데이터는 기존 API에서만 읽는다.
4. 탐색·비교·구간·예술 장면을 각각 별도 사이트로 만들지 않고 같은 앱의 보기 상태로 구현한다. 세부 패널은 API 결과와 함께 점진적으로 연결하고 브라우저에서 검토·조정한다.
5. 단면 기반 공간 표현과 코어·선택 전환을 실제 PC에서 시험한다. 1080p 30fps는 목표이며 확인 전에는 달성으로 기록하지 않는다.
6. 실제 계산과 화면 동기화가 안정되면 텍스트 AI·맥락 상태·음성을 연결하고, 발화 반응의 입력을 실제 응답 오디오로 바꾼다. BAZE 실계정 시험은 기존 사전 승인 규칙을 따른다.
7. 연속 실행·실제 음성·화면 가독성·녹화 품질을 확인하고 최종 영상을 편집한다.

현재 사용자가 준비할 키·계정·추가 데이터는 없다. 분석 시안의 시각 방향과 코어 레퍼런스는 제공된 상태다. 실제 화면을 보고 크기·움직임·정보량을 조정하면 된다. 추후 음성 연결 때 실제 마이크 권한과 음성 테스트, 촬영 때 녹화 권한이 필요할 수 있다.

## 7. 첫 구현 결과와 범위

`frontend/`에 React·TypeScript·Vite, Three.js·React Three Fiber를 구성했다. 중앙 타이틀은 약1.2초 뒤 이동을 시작하고, 2.6초에 코어가 등장하며 4.3초에 조작을 연다. 건너뛰기는 남은 타이머를 취소하고, 다시 보기는 중앙 타이틀부터 재시작한다. 움직임 축소 설정에서는 조작 가능한 화면으로 바로 진입한다. 코어는 자체 생성한 분절 구면·내부 궤도·외곽 입자이며 실제 뇌 데이터에서 추정한 구조가 아니다.

첫 분석 화면은 전체 영역 목록, 선택 ROI와 반대쪽 대응 ROI, Axial/Coronal 추천 단면과 ID 마스크, 정적 두께·부피, 전체 구간 Pearson 상관·두 z-score 파형이다. 색과 선 스타일로 구분하며 공통 세로축을 적용한다. 홈 왕복 시 선택을 유지한다. 아직 임의 두 ROI 선택·이동 창·단면 슬라이더·구간 재생·예술 모드·자연어 콘솔은 없다.

로컬 합성음 미리보기는 Web Audio의 실제 음량을 코어 밝기·크기에 연결한다. 시작·중지·자동 종료·화면 전환을 처리한다. AI·TTS·마이크 미연결을 화면에 명시한다. 실제 발화 연결 시 합성음 대신 응답 오디오를 사용해야 한다.

서버 버전 일치·요청 취소·오류/재시도·이미지 실패를 처리하며 초기 연결 완료를 `LOCAL DATA / LOADED`로 표시한다. 지속적인 서버 감시를 구현한 것은 아니다. 낮은 창에서는 좌우 패널을, 좁은 창에서는 분석 공간을 스크롤해 내용을 읽는다. 실제 확인은1280×720 가로 화면과 앱 패널에서 수행했다. 자동 검사6개와 타입·프로덕션 빌드가 통과했고 접근 차단은 로컬 HTTP로 확인했다. 독립 코드 검토는 도구 할당량 제한으로 미완료다. OS 움직임 축소 설정·모바일/다른 브라우저·1080p30fps 녹화 성능은 아직 실제 검증하지 않았다.

실제 실행 스크린샷과 로컬 검증 기록은 `reports/frontend/`에 보관하고 Git에서 제외한다. 원본·가공 패키지·환경 파일을 수정하거나 외부로 전송하지 않았다. npm 패키지 설치 외에 BAZE·LLM·STT·TTS 요청과 크레딧 사용은 없다. 실행 방법은 [README](../README.md#첫-프런트-화면-실행)를 따른다.

## 8. 다음 구현의 합의된 화면·상호작용

### 8.1 오늘 브리핑에서 분석으로

시작 타이틀→왼쪽 위 정착→중앙의 푸른 코어와 펼쳐진 하단 텍스트·음성 입력창 순서다. “오늘 해야 되는 거 알려줘” 요청에서 춘천 날씨·등록한 오늘 수업·할 일과 뇌 데이터 분석 과제를 브리핑한다. 설명한 정보는 오른쪽 위에 날씨·수업·할 일의 작은 카드로 정리한다. 각각 클릭하면 받은 내용의 상세를 펼치고, 분석 패널과 겹치지 않게 배치한다.

날씨는 앱용 웹 검색/조회 도구로 공개 정보를 확인하는 접근을 채택한다. 기상 전용 API의 직접 연동은 필수로 두지 않는다. 검색 제공자·BAZE에서 사용 가능한 기능·비용·출처 신뢰성은 아직 확인하지 않았다. BAZE 키만으로 개발 에이전트의 검색 도구가 앱에 제공되는 것은 아니다. 조회 출처·예보 대상 날짜·확인 시각을 표시하고 실패 시 예보를 생성하지 않는다.

수업·과제는 사용자가 제공한 개인 시간표·할 일 자료를 로컬에서 날짜·시각과 대조한다. 학교 로그인·DB 연동은 첫 범위에 포함하지 않는다. 등록되지 않은 수업·과제·휴강을 추정하지 않는다. 개인 자료는 Git에서 제외하고 외부 모델에 통째로 보내지 않는다.

“그럼 뇌 데이터 분석 과제부터 시작하자” 같은 실행 요청을 받으면 실제 도구를 호출해 전체 구성→관계 검색→두 영역 강조→파형·구간별 결과 순으로 분석을 진행한다. 현재의 탐색 버튼 대신 대화·실제 도구 결과로 전환한다. 중앙 뇌 표현·좌우 확대·관계선·하단 두 파형·선택 구간·커서를 시안의 공간 배치에 맞춰 전개한다. 계산 전에는 빈 결과/진행 상태를 표시하고 결과가 준비된 뒤 해당 표현을 연다. 실제 단면·마스크·시계열과 창작 조형을 구분한다.

### 8.2 한 요청이 끝난 뒤 다음 요청

사용자 최신 지시: “잠깐 멈춰”, “이 부분 설명해줘”, “둘만 크게 보여줘”를 포함한 후속 요청은 현재 요청이 끝난 뒤 받는다. 처리 중 끼어들기·추가 요청 대기열은 첫 구현에 넣지 않는다.

- 요청 처리 범위는 도구 실행·결과 반영·초기 화면 전환·응답 오디오 재생 종료까지다. 응답 오디오가 없으면 나머지 작업 완료로 종료한다.
- 처리 중 텍스트 전송·마이크 시작·추가 분석/상세 실행을 비활성화하고 처리 상태를 표시한다. 새 요청을 몰래 저장하거나 자동 실행하지 않는다.
- 이미 받은 날씨·수업·할 일 카드를 읽기 위해 펼치는 것은 허용하되, 새 조회를 발생시키는 조작은 완료 후에 받는다.
- 완료 후 뇌 영역·결과·그래프의 상세 선택과 후속 대화를 활성화한다. 실제 오류·오디오 실패 시에도 상태를 정리해 입력 잠금이 남지 않게 한다.
- 코어의 대기 회전·결과 커서의 자동 표시는 요청 완료 후에도 가능하다. 지속되는 시각 효과 때문에 다음 요청을 영구 차단하지 않는다. 완료 후의 “잠깐 멈춰”는 이 자동 표시를 제어할 수 있다.

### 8.3 입력창과 코어 위치

대화 홈에서는 하단 입력창을 펼친다. 분석 화면에서는 최하단 T·마이크 아이콘으로 접고, T는 텍스트·최근 대화를 펼치며 마이크는 실제 음성 입력을 시작한다. 처리 중에는 두 아이콘의 새 요청 시작을 막는다. 듣기 표시는 실제 녹음 중에만 사용한다. 입력창을 닫아도 대화·분석 선택을 유지한다.

분석 화면의 코어는 왼쪽 위에 더 크게 남긴다. 1080p 구도에서 실제 구체 지름160~200px를 초기 배치 목표로 검토하며 현재 달성치가 아니다. 브랜드·좌측 ROI 패널과 겹치지 않게 코어 공간을 확보하고 좁은 창에서는 조정한다. 홈과 분석은 같은 코어와 발화 상태를 유지한다.

### 8.4 코어 조형 개선 제안

현재는 선·동심 궤도 중심의 첫 구현이다. 다음 시각 개선은 중앙의 빛이 응집된 핵, 안쪽에서 흐르는 입자·짧은 신호 조각, 서로 다른 축의 분절 곡면 띠·반투명 패널, 외곽 궤도·스캔선으로 깊이를 만든다. 푸른색·청록·차가운 흰색을 유지하고 전체 회전 속도는 현재의2~3배를 시작점으로 실행 화면에서 조정한다. 모든 층을 같은 속도로 돌리지 않는다. 효과 추가와 성능 달성은 별개이며 실제 PC에서 확인한다.

발화 중에는 실제 출력 오디오를 AnalyserNode로 측정해 핵의 광도·띠의 미세한 팽창·입자 흐름에 연결한다. 무음에서는 가라앉고 재생 종료와 함께 대기로 돌아간다. 홈과 왼쪽 위 코어 모두 같은 반응을 사용한다. 지금의 합성음 검증은 실제 TTS 연결 완료를 의미하지 않는다.

우선 기존 Three.js의 절차적 기하·재질/셰이더로 개선한다. Blender는 정교한 외피·조각 모델이 필요할 때 제작해 GLB로 가져오는 선택 도구다. 사전 렌더 영상만으로 실제 발화 반응을 대체하지 않는다. 현재 설치를 요구하지 않으며, 실시간 시안을 검토한 뒤 필요를 판단한다.

## 9. 코어 개선·공통 화면 추가 구현

사용자가 이 범위의 구현을 승인했다. 기존 의존성만 사용했고 Blender·새 패키지·실계정 API는 사용하지 않았다.

- **코어:** 분절된 구면 패널, 내부 궤도·핵, 절차적으로 만든 발광 텍스처·외곽 입자를 추가했다. 외곽 회전은0.065→0.18rad/s, 내부 회전은0.13→0.34rad/s로 바꾸고 서로 다른 축·방향으로 움직인다. 실제 AnalyserNode 음량을 부드럽게 반영해 크기·광도·패널·입자 밝기를 바꾼다. 현재 오디오 입력은 계속 로컬 합성음 미리보기다.
- **코어 위치:** 분석 화면의 코어를 별도 왼쪽 공간에 크게 배치했다. 1280×720에서 캔버스215×200px를 확인했고 좌측 영역 선택 패널은 그 아래에 둔다. 값은 캔버스 크기이며 실제 구체 지름과 구분한다.
- **공통 입력:** 홈의 펼쳐진 텍스트 입력·마이크 안내, 분석의 접힌 T·마이크 버튼을 구현했다. 모드·화면 전환에서 초안을 메모리에 유지하며 외부 전송·파일 저장은 없다. AI 전송은 비활성이고 마이크 버튼은 미연결 안내만 연다. 실제 녹음·권한 요청은 없다.
- **보조 카드:** 날씨·수업·할 일의 펼침/닫기·Escape·초점 복귀를 구현했다. 조회 미연결·시간표 미등록·목록 미등록을 표시하며 예보·개인 수업·과제를 생성하지 않는다. 분석 화면에서는 작은 카드로 정리하고 선택한 상세만 임시로 겹쳐 표시한다.
- **검토용 조작:** 기존 API 분석 화면은 하단의 ‘분석 화면 미리보기’로 열 수 있다. 이는 실제 AI 명령으로 전환한 것이 아니다. 음량 미리보기 중에는 새 입력·화면 전환·기존 분석 조작을 막고 종료 시 복구한다. 전체 AI 요청의 순차 처리·자동 분석·상세 선택 잠금은 후속 단계다.

`Interface.tsx`는 카드·입력창, `interface.css`는 새 공통 화면, `model.ts`는 기하·모션·입력창 전환 규칙이다. 초기 화면의 사용하지 않는 버튼·푸터 스타일은 제거했다. Node 검사9개와 타입·빌드, 실제 브라우저의 입력/모드 전환·초안 유지·카드·오디오 잠금/종료·기존 API 연결을 확인했다. 독립 정적 검토에서 발견한 키보드 초점 손실을 재현한 뒤 수정하고 브라우저로 재검증했다. 현재 검증은1280×720와 실제 앱 창에서 수행했으며, 이 버전의 모바일·OS 움직임 축소·1080p 녹화 성능은 실제 확인하지 않았다. 관련 기록·실제 스크린샷은 `reports/frontend-v2/`에 보관한다.

**남은 순서:** 프런트의 분석 무대 확장→추가 백엔드 도구와 요청 상태 연결→승인된 BAZE 실제 도구 호출→실제 음성→영상 제작. 다음 프런트 작업은 중앙 단면의 공간 표현·ROI 확대·관계선·선택 구간·자동 커서이며 이번에 완료한 것으로 보고하지 않는다.

주석6의 공간감 있는 뇌 표현과 실제 MRI 병치는 후속 분석 무대 확장에 속한다. 실제 요청→중앙 브리핑→오른쪽 위 카드 이동, 실제 AI 준비/분석 상태·자연어 전환도 이번에 구현하지 않는다. 기존 실제 MRI·마스크·좌우 비교 API 조회와 명시된 화면 미리보기는 유지한다.

좌우 패널의 내용이 화면 높이보다 긴 창에서는 내부 스크롤을 만들지 않고 분석 공간 전체를 스크롤한다. 선택 패널 배경은 불투명하게 해 스크롤 시 뒤의 코어가 본문을 가리지 않게 한다. 초안 유지·키보드 초점·미연결 안내와 전송 비활성 규칙은 유지한다.

이번 검사·실제 화면·보존 대조 기록은 Git 제외 경로 `reports/frontend-feedback/`에 둔다. 기존9개 검사와 타입·빌드, 실제 앱 창 및1280×720의 UI를 확인한다. 모바일·다른 브라우저·1080p 녹화 성능은 별도 확인 대상이다. Python 백엔드·분석 수식·가공 패키지·원본·환경 설정은 이번 변경 대상이 아니다.


## 11. 높이 대응·입력 전환·선택 메뉴 정리 (2026-10-21)

사용자가 앞선 UI 수정안을 승인했고 분석 구간은 `1~200`으로 지정했다. 10절의 낮은 데스크톱 창에서 전체 스크롤을 허용한 배치는 이번 조정으로 갱신한다.

- 고정720px 최소 높이를 제거하고 데스크톱의 실제 화면 높이에 맞춰 코어 크기·여백·중앙 MRI·파형 높이를 조정한다. 820px 이하 높이는 좌우 패널 간격·보조 표기를 줄이며 분석 수치·해석은 유지한다. 아주 낮거나 좁은 창에서는 전체 스크롤을 최후의 대안으로 유지한다.
- 입력창을 펼치면 분석 공간 하단 여백도 함께 확보해 파형을 가리지 않는다. 펼침/접힘은0.32초 너비·높이·투명도 전환, 텍스트/음성 안내 전환은0.3초 등장 효과다. 닫힌 패널은 DOM에 남겨 종료 전환을 유지하되 inert·aria-hidden으로 키보드·보조 기술에서 제외한다. 초안은 그대로 보존하고 열림 완료 시 초점을 복원하되 사용자가 다른 패널로 옮긴 초점은 빼앗지 않는다.
- 왼쪽에는 현재 ROI·방향·추천 단면·구조 지표를 먼저 표시한다. `직접 변경`을 열면 기존 영역·방향 메뉴가 나온다. 중앙 클릭 선택·AI에 의한 영역/방향 선택은 아직 구현하지 않았다. 기존 API의 추천 단면 번호 선택은 유지한다.
- 분석 구간과 파형 헤더는 `1~200`으로 통일한다. 샘플 번호이며 실제 초가 아니다.

### 크롬 실측과 녹화 기준

실제 Chrome 확장 연결로 확인했다. 변경 전 최초 기본 페이지1920×911에서 분석 컨테이너646px에 내용732px이 들어가 스크롤이 발생했다. 창 크기 시험 설정을 해제한 뒤 기본 페이지는1920×855로 측정되어 이 크기도 추가 확인했다. 크기 시험은1280×720·1440×900·1920×1080의 페이지 영역을 사용하며 실제 모니터 해상도나 녹화 성능 시험과 구분한다. 기록·스크린샷은 Git 제외 경로 `reports/frontend-responsive/`에 둔다. 시험 후 크기 강제 설정은 해제한다.

촬영은 크롬에서 로컬 앱 실행→전체 화면 구도 확인→OBS로 화면·사용자 마이크·앱 응답 오디오 녹화→편집·MP4 출력 순서를 기본안으로 삼는다. 이번에는 OBS 설치·녹화·프레임 성능·실제 음성 수음을 실행하지 않는다. 참고: https://obsproject.com/kb/quick-start-guide

### 음성 단계의 세션 동작

마이크는 대화 세션을 한 번 활성화하면 발화마다 다시 누르지 않는 방향이다. 듣는 동안 실제 입력 음량·인식 중 문장·확정 문장을 보여준다. 발화 종료 판정 후 요청을 처리하고 응답 오디오가 끝날 때까지 다음 요청 인식/전송을 중지한다. 완료하면 켜져 있는 세션의 듣기를 재개하며 사용자가 끄거나 권한/인식 오류가 나면 종료 상태를 표시한다. 브라우저·서비스의 인식 종료 이벤트와 오류 복구도 별도로 처리해야 하므로 단순 continuous 옵션만으로 무기한 작동을 보장하지 않는다. 앱 시작부터 음성으로만 호출하는 상시 호출어 감지는 별도 검토 대상이다.

이번 화면은 여전히 미연결 안내다. STT·TTS·마이크 권한 요청·외부 음성 전송은 추가하지 않는다. 실제 STT 제공자·한국어 중간 결과·로컬 처리 여부·비용을 확인하고 기존 실계정 테스트 승인 규칙 안에서 연결한다. 참고: https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/continuous

## 12. 공통 입력창·분석 무대 확장 (2026-10-22)

사용자가 승인한 두 범위를 기존 화면에 구현했다. 새 라이브러리·Blender 설치 없이 React·Three.js/R3F·Canvas2D·SVG와 기존 로컬 FastAPI를 사용한다.

- **공통 입력:** 텍스트와 음성 모드가 같은 편집 가능한 입력칸을 공유한다. 마이크 버튼으로 전환해도 초안·커서를 유지하고 입력칸이 부드럽게 펼쳐진다. 음성 모드는 마이크 아이콘과 `STT 연결 전 · 마이크 꺼짐`을 표시한다. 실제 듣기·받아쓰기·전송을 흉내 내지 않는다. 홈은 펼침, 분석은 T/마이크로 접고 열며 Escape로 닫는다.
- **실제 분석 선택:** `분석 화면 미리보기`를 열면 기존 `/api/analysis/pairs`로 좌우 대응 쌍 중 Pearson r가 가장 높은 쌍을 찾는다. 비교·50샘플 창/10샘플 간격의 창별 상관·두 방향 단면 목록을 조회한다. 두 ROI가 함께 잘 보이는 방향·단면을 자동 선택한다. 영역이나 방향은 완료 후 `직접 변경`에서 바꿀 수 있다. 검색·계산·이미지 준비 중에는 결과 조작과 입력을 잠그고, 실패 시 오류·재시도를 표시한다. 취소된 이전 응답은 새 선택을 덮지 않는다.
- **중앙 무대:** 실제 T1 PNG의 밝기와 ID 마스크 픽셀로 최대 다섯 단면의 푸른 점군을 메모리에서 만든다. 선택 영역의 색·마스크 위치를 유지하고 양쪽 중심을 표시용 곡선으로 잇는다. 실제 MRI·마스크는 작은 창으로 병치하고 확대할 수 있다. 단면 사이 깊이·회전·관계선은 시각 연출이며 정밀 3D 복원·직접 신경 연결이 아니다.
- **좌우와 하단:** 각 ROI의 실제 단면 확대·현재 z-score, 구조 지표와 전체/선택 창의 상관을 표시한다. 실제 두 파형·구간 강조·현재 샘플 커서·재생/일시정지·슬라이더를 연결했다. 창 막대를 선택하면 해당 구간의 상관과 재생 범위를 함께 바꾼다. `1~200`은 샘플 번호이고, `10 samples/s`는 표시 속도이며 TR·초 단위 획득 시간으로 해석하지 않는다. z-score는 전체 기록 기준을 유지한다.
- **상세·상태:** 분석 완료 후 ROI 카드·중앙 영역 표식·MRI를 클릭하면 상세 창을 연다. 상세를 열면 샘플 재생을 멈추고 Escape로 닫으면 원래 버튼에 초점을 돌린다. 홈 이동·오디오 미리보기·문서 숨김에는 재생을 멈추고 분석 무대의 WebGL 루프도 비활성화한다. 움직임 축소 설정에서는 자동 샘플 재생을 시작하지 않는다. 상단 로컬 분석 상태와 AI 연결 전 상태를 구분한다.

구현은 `Interface.tsx`·`AnalysisView.tsx`·`BrainStage.tsx`·`stageData.ts`·`analysisModel.ts`와 `stage.css`에 있다. 실제 이미지는 로컬 API로만 읽고 파일·공개 자산을 새로 만들지 않는다. 원본·가공 패키지·환경 파일은 변경하지 않았다.

### 검증과 현재 한계

Node 합성 검사13개와 TypeScript·프로덕션 빌드가 통과했다. Chrome에서 로컬 함수로 별도 계산한 검색 쌍·전체/창별 상관·현재 샘플 값을 화면과 대조했다. 입력 모드·초안·초점·홈 왕복, 수동 ROI/Coronal 변경, 재생·창 선택·상세/MRI 확대와 Escape 복귀를 확인했다. 기본1920×855와 시험1280×720·1440×900·1920×1080에서 페이지 넘침을 확인했으며, 최종1280×720 음성 입력창 펼침에서도 좌우 패널·중앙/파형에 내부 넘침이 없다. 시험 크기는 복원했다. 독립 정적 검토의 숨긴 탭에서 로딩 완료 후 재생 재시작 문제를 수정했고 상세 창 이름·카드/상세 단면 일치도 보완했다.

기록·실제 스크린샷은 Git 제외된 `reports/analysis-stage/`에 있다. 원본105개 기준 해시·가공71개·manifest·`.env`가 작업 전과 일치한다. BAZE·STT·TTS 요청, 크레딧 사용, 커밋·푸시는 없다. HTTP 실패·버전 혼용은 가짜 fetch 단위 검사로 확인했으며, 실제 서버 중단·WebGL 실패·OS 움직임 축소·모바일·1080p 녹화 FPS는 이번에 재검증하지 않았다. Chrome 자동화에서는 다른 탭을 열어도 `document.hidden=false`여서 숨김 중 로딩 완료의 실제 타이밍은 재현하지 못했다. 해당 경로는 가시성 조건과 루프 중지 코드를 정적으로 검토했다. 큰 JS 번들 경고는 남아 있다.

### 다음 단계와 사용자 준비

다음은 백엔드에 명령→도구→결과/화면 상태의 요청 제어를 연결하고, 승인된 소규모 BAZE 테스트 후 자연어로 화면을 조작하는 단계다. 이어 실제 STT/TTS·호출어·오늘 브리핑, 마지막에 Chrome/OBS 연속 실행 촬영·편집을 진행한다. 현재 사용자가 설치하거나 추가로 결정할 필수 항목은 없다. 음성 단계에는 실제 마이크 허용·한국어 발화 확인과 처리 방식/비용 결정, 촬영 단계에는 OBS 설치·화면/소리 캡처 확인이 필요하다. 유료 요청은 기존 규칙대로 테스트 내용·횟수·예산을 먼저 제시하고 승인을 받는다.

## 13. 일반 3D 뇌 모형으로 교체하는 후속 합의 (2026-10-22)

사용자는 중앙의 단면 점군 대신 일반적인 영역별 3D 뇌 모형을 원한다. 실제 제공 MRI/마스크는 좌우 패널의 근거 이미지로 유지한다. 좌 패널=좌반구, 우 패널=우반구로 고정하고 이미지·수치·파형·색 순서를 함께 맞춘다. 좌측은 청록, 우측은 금색으로 연결한다. 영역 전환은 강조와 카메라가 부드럽게 이동하도록 한다. 모형은 제공된 사람의 뇌 복원이나 동일한 atlas 경계를 뜻하지 않는다.

별도 세션이 Blender MCP로 공개 모델의 품질·조건·영역 분리를 확인하고 편집/GLB 전달을 맡는다. 기존 웹 세션은 모델을 받아 렌더·선택·시계열 발광·좌우 실제 단면을 연결한다. 현재 이 교체는 미구현이며 12절의 단면 무대가 실행 중이다. 모델 후보·연결 확인·산출물 규격·원본 보호는 [Blender 작업 인계](BLENDER_HANDOFF.md)를 따른다. 이번 분담에서는 기존 서버/프런트와 모델 작업 파일을 서로 덮어쓰지 않는다.
