# NERVIS 프로젝트 기획 및 진행 기준

갱신: 2026-10-21, Asia/Seoul. 사용자가 선택한 음성 상호작용 시나리오를 현재 설계 기준으로 반영했다. **데이터 검사·탐색 분석은 완료했고, 아래 시스템과 영상은 앞으로 구현·제작할 계획이다.** 기술의 채택 계획과 설치·실호출 검증 완료를 구분한다.

## 1. 만들 작품

NERVIS는 제공된 뇌 데이터를 음성 대화로 탐색하는 인터랙티브 AI 시스템이다. 사용자가 “NERVIS”라고 부르면 인터페이스가 활성화되고, 질문에 따라 실제 데이터 분석과 영역 선택·비교·시각화가 실행된다. 그 상호작용을 녹화·편집한 MP4가 공모전의 주 제출물이다.

작품의 중심 경험은 **질문으로 뇌의 형태·변화·관계를 발견하는 과정**이다. 뇌 모양이 나타나는 장면에서 시작해, 닮은 신호를 찾고, 두 영역을 비교하고, 구간에 따른 차이를 묻고, 그 결과를 예술적 표현으로 확장한다. 시간점 재생은 이 탐색을 돕는 기능이다.

NERVIS의 목소리는 데이터를 탐색하는 시스템의 목소리다. 제공된 뇌의 소유자나 그 사람의 생각·기억을 재현하는 인격으로 설정하지 않는다. 시각적 분위기는 SF 분석 인터페이스에서 영감을 받되 NERVIS의 명칭·그래픽·음성·음악을 직접 구성한다.

## 2. 제출 조건과 현재 결정

| 항목 | 기준과 근거 |
|---|---|

| 제출 형태 | 영상·음성·이미지 파일. 이번 작품은 MP4를 중심으로 제작 |
| 실제 프로그램 | 제작·촬영에 사용. 실행 파일이나 현장 프로그램 시연을 제출의 전제로 삼지 않음 |
| 주최자 확인 | 사용자가 공유한 안소라 교수님의 후속 이메일에서, 구현한 시스템의 음성 명령·분석·시각화 과정을 녹화·편집해 MP4로 제출하는 방식을 승인 |

공고 PDF에 영상 길이·해상도·용량 상한이 기재되어 있지 않았다는 기존 검토를 기준으로 한다. 최종 제출 전 제출 창의 최신 제한·요구 파일명을 확인한다. 교수님 이메일은 사용자가 제공한 확인 이력으로 기록하며, 이메일 원문·주소를 공개 문서에 옮기지 않는다. [공고 원문](AI%20Brain%20Art%20Challenge%20-%20안소라.pdf)

## 3. 프로젝트가 어떻게 바뀌는가

| 항목 | 데이터 수령 전 기획·초기 검토 | 현재 진행 기준 |
|---|---|---|
| 기획 근거 | 데이터의 형태·범위를 예상 | 검사한 20개 ROI, 200개 BOLD 시간점, 33개 MRI 단면을 사용 |
| 사용 경험 | “뇌를 분석해줘”라는 넓은 아이디어 | 선택·비교·후속 질문이 이어지는 음성 탐색 |
| AI 역할 | 음성·AI의 구체적 역할을 검토 | BAZE/HAI GPT 모델이 맥락을 해석하고 허용된 도구를 호출 |
| 분석 | 구현 전에 가능성을 검토 | 기존 분석을 재사용하고 요청한 구간·대상에 맞춰 계산 |
| 화면 | 홀로그램·3D 등의 표현 후보 | 실제 단면·라벨 마스크를 바탕으로 한 탐색 화면과 입체적 연출 |
| 데이터 변화 | 구조와 신호의 구분을 정리하는 단계 | 형태는 고정하고, BOLD 상대 변화·관계에 따라 표시를 바꿈 |
| 결과물 | 실행·전시 방식 검토 | 실제 시스템 녹화 + 편집 + 필요한 생성 영상으로 완성한 파일 |
| 다음 작업 | 데이터를 이해하고 방향 결정 | 앱용 데이터 패키지와 실제 명령 실행 경로 구현 |

이 문서와 연결 문서가 현재 기획이다. `past/`의 옛 기획을 다시 구현 요구사항으로 승계하지 않는다.

## 4. 핵심 시스템 시나리오

1. 사용자가 마이크를 활성화하고 “NERVIS”라고 부른다. 호출어가 인식되면 화면이 열리고 짧게 응답한다.
2. “가장 비슷하게 변하는 두 영역을 찾아줘.” 전체 20영역의 지정 구간에서 유사도를 계산하고 해당 영역을 표시한다.
3. “둘만 보여줘.” 직전 선택을 유지해 두 ROI를 확대하고 파형을 나란히 배치한다. 두 ROI는 좌뇌·우뇌 전체와 다르다.
4. “처음부터 끝까지 계속 비슷해?” 같은 두 ROI를 여러 시간 창에서 다시 비교해 관계가 유지되는 정도를 보여준다.
5. “좌우가 덜 비슷한 영역도 찾아줘.” 좌우 대응 쌍으로 검색 대상을 바꿔 대비되는 사례를 계산한다.
6. “아까 영역으로 돌아가서 이 구간을 재생해줘.” 대화 맥락과 선택 구간에 따라 실제 화면을 조작한다.
7. “이 관계를 빛으로 표현해줘.” 현재 분석 결과를 정해진 시각 매핑에 연결해 작품 장면으로 전환한다.

위 문장은 촬영을 위한 예시다. 같은 뜻의 다른 표현이나 순서 변경에도 기능이 동작해야 한다. 화면·음성·지표의 실제 연결과 촬영 구성은 [VIDEO_SCENARIO.md](VIDEO_SCENARIO.md)에 정의한다.

## 5. 필수 범위와 이후 확장

| 우선순위 | 범위 | 완료 판단 |
|---|---|---|
| 필수 | 20 ROI와 구조·시계열·마스크의 공통 ID 연결 | 화면의 영역명·색·파형·두께·부피가 같은 ID를 가리킴 |
| 필수 | 실제 모델 API와 도구 호출 | 문장 해석 → 도구 실행 → 결과 → 화면 변경의 기록이 남음 |
| 필수 | 한국어 음성 입력·응답, 호출어 | 사용자가 마이크를 켠 세션 안에서 호출·명령·응답이 이어짐 |
| 필수 | 두 ROI 선택·유사도·구간별 비교 | 선택과 구간을 바꾸면 실제 계산 대상과 표시가 함께 바뀜 |
| 필수 | 실제 단면·영역 강조·비교 레이아웃 | 제공 이미지와 선택 마스크의 대응이 확인됨 |
| 필수 | 재생·정지·되돌아가기와 맥락 유지 | “둘”, “아까”, “전체”를 현재 상태와 함께 처리 |
| 필수 | 데이터 기반 예술 장면 | 밝기·움직임·선의 의미와 원자료 연결을 설명 가능 |
| 필수 | 녹화·편집·자막·AI 활용 보고서 | 최종 파일을 재생하고 제출 조건을 확인 |
| 선택 | Google 생성 영상 | 도입부·전환·마무리용 짧은 소재. 없어도 본편 완성 가능 |
| 선택 | PCA·스펙트럼·구조-신호 비교 UI | 핵심 음성 탐색이 안정화된 뒤 필요한 장면만 추가 |
| 선택 | 고급 입체 표현·Blender 렌더 | 단면 기반 본편을 완성한 뒤 남는 시간에 검토 |

현재 범위에 로그인·사용자 관리·클라우드 배포·DB·RAG·멀티에이전트·모델 학습을 넣지 않는다. 단일 PC에서 촬영할 시스템에 필요한 기능부터 만든다. 원시 fMRI 재전처리나 정밀 3D 복원을 수행할 입력은 제공되지 않았다.

## 6. 구현 방식 선택

| 방식 | 장점 | 한계 | 결정 |
|---|---|---|---|
| 로컬 웹 앱 + 실제 AI API + 화면 녹화 | 현재 Python 분석 재사용, 실제 상호작용, 화면 디자인과 촬영 가능 | 음성·API·브라우저 연결을 검증해야 함 | 본안 |
| 영상 생성 모델 중심으로 전편 제작 | 짧은 분위기 장면 제작에 유용 | 실제 수치·UI 동작·대화의 일관성을 보장하지 못함 | 영상 소재 제작에만 사용 |
| 오프라인 렌더 중심으로 제작 | 반복 렌더와 장면 통제가 쉬움 | 실시간 대화 시스템의 증명이 별도로 필요 | 필요시 보조 렌더 |

## 7. 사용할 기술

| 층 | 채택 계획 | 역할·선정 이유 |
|---|---|---|
| 웹 화면 | React + TypeScript + Vite | 상태에 따라 패널·선택·대화를 함께 갱신하고 로컬에서 실행 |
| 뇌·예술 시각화 | Three.js + React Three Fiber | 단면 평면·ROI 마스크·점·선·카메라 전환을 실제 데이터와 연결 |
| 분석 그래프 | Apache ECharts | 200점 파형, 상관행렬, 창별 변화, 구조 지표 비교 |
| 화면 전환 | CSS와 Three.js의 프레임 갱신 | 초기에는 별도 애니메이션 프레임워크를 추가하지 않음 |
| 로컬 서버 | Python + FastAPI + Pydantic + Uvicorn | 데이터·도구 인자 검사, 계산, 세션, 브라우저 통신 |
| 수치·이미지 | 기존 NumPy·pandas·SciPy·Pillow | 검증된 분석과 RGB→ROI 변환 재사용. Matplotlib는 보고서 그림용 |
| 대화 모델 | BAZE/HAI GPT Gateway의 GPT 계열 + OpenAI Python SDK | SDK는 호환 클라이언트이며 실제 목적지는 BAZE. GPT 도구 호출은 Responses API를 우선 검증 |
| 실시간 음성 인식 | BAZE Soniox 실시간 받아쓰기 + WebSocket | 한국어 음성을 텍스트로 변환. 서버가 키를 보관하며 중계 |
| 응답 음성 | BAZE Gemini TTS | 동적으로 생성된 짧은 응답을 합성. PCM 형식 처리 필요 |
| 외부 서비스 통신 | HTTPX + websockets | 미디어 API·견적·오류 처리와 실시간 음성 중계 |
| 선택 영상 생성 | BAZE의 Google Gemini Omni Flash 우선, Google 직접 API·Flow는 대안 | 동일 키로 가능한지 먼저 확인하고 도입·전환 소재 제작 |
| 촬영 | OBS Studio 우선 | 앱 화면·마이크·시스템 음성을 녹화. 설치·캡처 시험 필요 |
| 편집·출력 | Python + PyAV + Pillow | 컷 편집, 자막 합성, 음량·동기화, H.264/AAC 출력 |

라이브러리 버전은 설치 시 호환되는 안정 버전을 고정한다. React와 React Three Fiber의 메이저 버전을 맞추고, 새 alpha 버전을 제작 필수 조건으로 삼지 않는다. [R3F 호환 안내](https://r3f.docs.pmnd.rs/getting-started/introduction), [FastAPI](https://fastapi.tiangolo.com/), [ECharts](https://echarts.apache.org/en/index.html), [Vite](https://vite.dev/guide/)

현재 수치·이미지 분석 라이브러리와 PyAV는 기존 환경에서 사용 이력이 있다. 짧은 합성 영상의 H.264/AAC 인코딩·디코딩은 시험했지만, 본편 길이의 실시간 렌더·촬영·음성 성능을 검증한 것은 아니다. OBS·Blender·FFmpeg CLI는 앞선 환경 점검에서 발견되지 않았다. PyAV는 FFmpeg 라이브러리 바인딩이며 별도 FFmpeg 실행 파일의 설치 여부와 구분한다. [PyAV](https://pyav.org/docs/stable/), [OBS](https://obsproject.com/kb/quick-start-guide)

## 8. AI 연결과 Google 영상 모델 결정

- HAI GPT는 사용할 서비스이고, 요청의 `model`에는 해당 계정의 모델 목록이 반환한 정확한 ID를 쓴다. 특정 모델·실시간 음성·영상 기능의 계정 권한은 아직 확인하지 않았다.
- 앱의 대화 모델 연결과 개발용 Codex CLI 연결은 서로 다른 설정이다. 앱을 BAZE에 연결했다고 코딩 에이전트가 자동으로 바뀌지 않는다. [BAZE_API_GUIDE.md](BAZE_API_GUIDE.md)
- Google의 현재 영상 생성 기본 권고는 Gemini Omni Flash다. **Veo 3.1 Preview와 Gemini Omni Flash Preview는 2026-10-22 종료 예정**이므로 이번 제작의 기준 모델로 잡지 않는다. [Google 영상 개요](https://ai.google.dev/gemini-api/docs/video), [Google 가격·종료 안내](https://ai.google.dev/gemini-api/docs/pricing)
- BAZE 문서는 Google 영상 모델 `google/gemini-omni-flash/v1.1`을 안내한다. Google 직접 API의 ID `gemini-omni-1.1-flash`와 구분한다. 계정에서 가능한 경로·비용을 확인한 뒤 짧은 소재부터 만든다. [BAZE 영상 API](https://docs.mindlogic.ai/docs/hallym-ac/api-gateway/reference/video-generation)
- Google 생성 영상은 사전에 제작하는 소재다. 음성 명령마다 영상을 생성하는 기능을 본 시스템의 필수 흐름에 넣지 않는다. [GOOGLE_VIDEO_WORKFLOW.md](GOOGLE_VIDEO_WORKFLOW.md)

## 9. 데이터와 표현의 기준

원본 `C:\NERVIS\뇌영상 시계열 예시 데이터`는 모든 단계에서 읽기만 한다. 입력의 사실은 [DATA_OVERVIEW.md](DATA_OVERVIEW.md), 계산의 근거는 [DATA_ANALYSIS_RESULTS.md](DATA_ANALYSIS_RESULTS.md)를 따른다.

- 시간 변화는 20 ROI의 BOLD 값 변화다. 뇌 형태·두께·부피가 시간에 따라 변한 자료는 아니다.
- 제공된 좌 10·우 10 ROI는 선택된 영역 집합이다. “좌우 전체 비교”도 이 집합의 비교로 설명한다.
- “둘만 꺼내기”는 선택 ROI 마스크의 강조·크롭·배치 변경이다. 정밀한 실제 3D 덩어리 추출이라고 부르지 않는다.
- 단면 번호를 깊이로 배치하는 입체 연출은 상대적 구성이다. 두 방향의 이미지를 물리적으로 정합한 3D 복원으로 제시하지 않는다.
- 신호의 유사성은 함께 변하는 정도다. 직접 신경 섬유·인과·정보 전달 방향을 의미하지 않는다.
- 밝기·색·입자·소리의 매핑은 창작 규칙이다. 신경 활성·감정·질환·생각을 판독했다는 설명을 하지 않는다.
- 200점은 200초가 아니다. 화면은 시간점 번호를 사용하고 영상 재생 속도는 별도로 정한다.
- 원본·상세 파생 데이터의 외부 전송은 이용 조건 확인 전 허용하지 않는다. 모델 연결은 이 제한을 우회하는 근거가 아니다. 결과 요약의 허용 범위를 먼저 정하고, 미확인 동안 수치·상세 결과는 로컬 화면과 로컬 음성 출력으로 처리한다.

## 10. 개발 순서와 단계별 산출물

| 단계 | 작업 | 다음 단계로 갈 기준 |
|---|---|---|
| 0. 현재 | 데이터 검사·탐색 분석·기획 문서 | 기존 근거와 현재 기획 연결 완료 |
| 1. 데이터·API 준비 | 읽기 전용 원본에서 앱용 패키지 작성, 별도로 BAZE 모델 목록·키의 발급 호스트·도구 호출·음성 권한 확인 | 20 ROI 연결 검사와 합성 데이터 도구 호출 성공. 두 준비 작업은 병행 가능 |
| 2. 텍스트로 실제 동작 | 자연어 → 도구 → 실제 계산 → 상태 변경 → 근거 표시 | 문장과 구간을 바꿔도 요청대로 계산·선택 |
| 3. 화면 연결 | 실제 단면·마스크·그래프·영역 분리·재생 구현 | 선택한 ID·구간과 화면·수치 일치 |
| 4. 음성 연결 | 마이크·호출어·실시간 받아쓰기·응답 합성 | 한국어 후속 질문을 포함한 연속 대화 성공 |
| 5. 예술·연출 | 데이터 매핑, 카메라·빛·전환, 필요시 Google 소재 | 원자료와 창작 규칙을 구분한 장면 완성 |

데이터 처리를 처음부터 다시 조사하지 않는다. 기존 재현 코드의 계산을 재사용하되 앱용 패키지 생성은 별도 작업으로 만든다. 현재 분석 스크립트는 결과 폴더를 갱신하므로 앱 실행마다 전체 분석을 돌리는 구조로 사용하지 않는다.

## 13. 완성의 기준과 남은 확인

- 다른 표현·명령 순서에서도 실제 도구가 실행되고, 선택과 구간을 바꾸면 그 조건의 결과가 나온다.
- 설명·파형·색·영역·구간이 같은 분석 결과를 가리킨다. 실패 시 성공 응답을 내보내지 않는다.
- 호출어부터 후속 질문까지 실제 실행한 연속 장면을 확보한다. 편집본과 원본 촬영을 구분해 보관한다.
- 완성 영상의 음성·자막·화면이 맞고, 두 개 이상의 재생 환경에서 전체를 확인한다.
- AI 도구·모델·프롬프트·수정 과정·데이터와 창작 매핑을 보고서에 남긴다.
- 모든 가공·촬영 후에도 원본 105개 해시가 기존 기준과 일치한다.

남은 확인은 실제 키·계정별 모델과 크레딧, 한국어 인식·응답 속도, 로컬 TTS 사용 가능 음성, OBS 설치·캡처·본편 성능, 외부 전송 허용 요약 범위, 최종 접수 제한이다. 이것들은 설계 문서 작성만으로 검증되었다고 처리하지 않는다.
