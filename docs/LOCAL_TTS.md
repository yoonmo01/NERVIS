# 로컬 응답 음성 연결과 스트리밍 조사

## 합의한 입력 UI 재정리 — 사용자 검증 대기 (2026-10-28)

닫힌 상태는 중앙 T/마이크, 열린 상태는 공통 입력창 오른쪽 마이크/보내기로 구성한다.
열린 상태에서는 T를 표시하지 않는다. 중앙 그룹의 너비를 반응형으로 늘려 입력창과
오른쪽 버튼이 함께 이동한다. 고정 아이콘 왼쪽의 별도 팝업/위로 쌓이는 입력창은 사용하지 않는다.
T는 마이크를 켜지 않고 입력창만 열며, 마이크는 입력창을 열고 캡처를 시작한다.
준비 중/듣는 중을 구분하고 다시 누르면 중지·확정 후 수정할 수 있다. ×로 접을 때 초안을
보존하고 녹음을 중지한다. 마지막 확정은 접힌 상태에서도 초안에 반영할 수 있도록 한다.
이번 수정은 사용자가 직접 검증하기로 했으므로 테스트·빌드·브라우저 조작을 실행하지 않았다.
이 절이 아래의 고정 아이콘/왼쪽 팝업 배치 설명보다 우선한다.

## 입력창 방향 복원·백엔드 시작 시 대기 (2026-10-28)

입력창은 고정된 T/마이크 아이콘의 왼쪽에 절대 배치한다. 아이콘 위에 패널을 세로로 쌓지
않으며 홈과 분석에서 같은 방향으로 열린다. 현재 브라우저에서 T를 눌러 방향을 확인했다.

`python -m backend`의 일반 앱은 시작 시 설치된 VoiceStudio/OmniVoice/한국어 프로필을
확인하고 TTS를 미리 로드한다. 준비 후 `Local TTS ready`를 기록한다. 준비 불가 시 경고를
기록하고 뇌 분석/텍스트 서버는 계속 실행한다. 60초마다 음성 없이 warmup으로 VoiceStudio의
유휴 타이머를 갱신하며 다른 STT/TTS 작업 중이면 건너뛴다. 서버 종료 시 유지 작업을 취소한다.
유지 준비는 사용자 음성 세션과 별도 잠금을 쓰며, 준비 중 들어온 STT/TTS는 busy 오류 대신
준비 완료를 기다린다. 사용자가 연결을 닫으면 해당 대기는 취소된다.
이는 VoiceStudio 앱을 직접 실행하는 기능은 아니므로 VoiceStudio는 먼저 켜야 한다.
테스트/커스텀 앱 팩토리는 기본 자동 준비를 끄며 필요 시 `create_app(preload_speech=True)`로 켠다.

읽은 실제 로그에서 모델 로딩은 20:58:13→20:58:33 약20초, 이후 첫 음성은 약4.05초였다.
따라서 사전 로드는 냉간 모델 대기를 줄이지만 문장 생성 지연은 별도로 남는다.
GPU 모델 상주 메모리 사용과 네이티브 모델 로드의 복구 다운로드 한계는 아래 설명을 따른다.
이번 변경 검증에서는 실제 모델 로드·음성 생성·유료 요청을 실행하지 않았다.
브라우저의 열림/닫힘에서 아이콘 좌표가 x=515.34/y=890.90으로 동일함을 확인했다.
화면 기록은 로컬 `reports/tts-20261028/left-drawer-verified.png`다.
최종 합성 검증: 프런트51개, 새 venv 백엔드139개 중105개 통과/34개 DB opt-in 건너뜀,
타입/프로덕션 빌드 통과. 실제 서버 시작 시 모델 준비·장시간 상주·지연 개선은 아직 실측하지 않았다.

## 유휴 모델 자동 로드·입력 UI 단순화 (2026-10-28)

사용자가 보고한 음성 실패를 진단할 때 VoiceStudio 0.5.7은 정상 응답했고 JARVIS/JARVIS_2는
Korean이었다. /model/status는 idle / loaded=false였고 로그에는 유휴 자동 해제가 기록돼 있었다.
기존 NERVIS는 미로드 모델을 즉시 거절했으므로 이 상태에서 TTS가 실패하는 원인을 확인했다.
새 코드는 모델 미로드 시 설치된 k2-fsa/OmniVoice와 활성 omnivoice 엔진을 먼저 확인하고
/setup/warmup으로 메모리 로드 후 상태를 기다린다. 이미 로딩 중이면 중복 warmup을 보내지 않는다.
NERVIS는 모델 설치 API·다른 엔진 선택·프로필/환경 파일 수정은 하지 않는다.
단, VoiceStudio 자체 warmup은 내부적으로 from_pretrained를 사용하므로 손상된 캐시의
복구 다운로드나 모델 경로 override의 네트워크 접근까지 NERVIS가 차단하는 것은 아니다.
정상 설치 캐시 재사용을 전제로 하며, 완전한 오프라인 보장은 별도 앱 설정/네트워크 검증이 필요하다.
모델 미설치/로드 실패/프로필 불일치를 프런트에서 구분해 표시한다.
로드 대기 중에도 브라우저 연결 종료를 감시해 중지/탭 숨김 시 NERVIS 대기와 공통 잠금을
해제한다. VoiceStudio 내부에서 이미 시작한 로드 작업 자체는 계속될 수 있다.

홈도 초기에는 T·마이크 아이콘만 표시한다. T는 공통 입력창 열기/닫기, 마이크는 한 번 눌러
음성 입력창을 열고 실제 캡처 시작, 다시 눌러 캡처 중지와 마지막 확정 대기를 수행한다.
별도의 마이크 켜기 줄과 모드 전환 버튼은 제거했다. 초안·중간/확정 결과·오류는 보존한다.
TTS/요청 처리 중 마이크 시작 금지·탭 숨김 정리는 유지한다.

실행 중 백엔드는 사용자가 직접 켠 서버이므로 임의 재시작하지 않았다. 사용자는 백엔드를
Ctrl+C 후 `.venv/Scripts/python.exe -m backend`로 다시 실행하고, 초안이 있으면 복사한 뒤
브라우저를 새로고침해 초기 접힘 상태를 확인한다. 더미 브리핑 자동 TTS부터 재시험한 뒤
실제 AI 조회→TTS를 확인한다. 실제 AI 호출에는 크레딧이 사용된다.

## 최신 기본 출력: 자동 TTS (2026-10-28)

사용자 요청으로 새 요청의 정상/부분 성공 응답과 화면에 표시하는 요청 오류는 자동으로 읽는다.
텍스트/마이크는 입력 방식이며 출력 음성을 끄는 선택은 없다. 기존 세션 기록을 불러왔다는 이유로
과거 응답을 다시 읽지는 않는다. 음성 실패는 화면에 표시하며 원래 응답을 보존하고 입력 잠금을 해제한다.
브라우저 자동 재생을 위해 보내기 클릭/Enter 시 AudioContext를 미리 준비한다.
탭 숨김/페이지 종료는 재생을 중지하며 숨김 중 도착한 응답을 뒤늦게 자동 재생하지 않는다.

프런트의 프로필 선택과 응답 읽기 버튼은 제거했다. 재생 중 **음성 중지**만 표시한다.
실제 `.env`는 변경하지 않았으며 다음 설정을 추가/수정하면 다음 TTS 요청에 반영한다:

```dotenv
NERVIS_VOICESTUDIO_VOICE=JARVIS
```

VoiceStudio의 저장 음성 프로필 이름 또는 ID를 사용한다. 예: JARVIS_2 / 8f10d4a1.
이는 합성 엔진 이름과 다르며 엔진은 설치된 로컬 OmniVoice를 유지한다.
기본값은 JARVIS, OS 환경 변수가 `.env`보다 우선한다. 없거나 중복된 이름/한국어가 아닌
프로필은 명시 오류이며 다른 목소리로 조용히 바꾸지 않는다. 브라우저는 음성을 지정할 수 없다.
입력 길이/시간/오디오 제한과 VoiceStudio 실행·OmniVoice 로드 조건은 유지한다.
아래 수동 읽기 설명은 최초 구현 이력이다.

자동 출력 변경 후 프런트51개·백엔드134개 중100개 통과/34개 DB opt-in 건너뜀·타입/빌드를
확인했다. 별도 실계정 AI 호출과 자동 TTS의 실제 청취는 하지 않았다. 기존 원본105개와
환경 파일/가공 패키지 등 보호74개 파일 해시는 유지됐다.

2026-10-28. 사용자 요청: 통합 검증 전에 TTS 코드를 연결하고 시험은 미룬다.
초기 코드 연결에서는 실제 음성 생성/재생·마이크·테스트·빌드·유료 AI 시험을 보류했다.
구현/정적 검토와 동작 검증을 구분한다. 원본과 환경 파일·VoiceStudio 설정은 보존한다.

## 설계와 구현 계획

기존 응답 본문(model_acknowledgement)만 로컬 TTS에 전달한다. 데이터 배열·원본 파일·경로를
TTS 입력으로 조립하지 않는다. 기존 응답을 임의로 자동 재생하지 않고 **응답 읽기/중지**로
시작한다. 저장된 JARVIS(f0c26d84)를 기본으로 JARVIS_2(8f10d4a1)도 선택할 수 있다.
프로필은 읽기만 하고 변경하지 않는다. AI 자동 전송·호출어·상시 마이크는 추가하지 않는다.

- [x] `backend/tts.py`: 고정 loopback VoiceStudio WebSocket 중계, 입력/PCM 검증, 상태·시간 제한.
- [x] `frontend/src/tts.ts`, `useSpeech.ts`: PCM 도착 즉시 순서대로 Web Audio 예약·실제 음량 측정·중지/종료 정리.
- [x] `App.tsx`, `model.ts`, `interface.css`: 프로필/읽기/중지, STT와 동시 사용 차단, 실제 음량 기반 코어.
- [x] `tests/test_tts.py`, `frontend/tests/tts.test.ts`: 네트워크/음성 없는 합성 검사를 작성하되 이번에는 실행하지 않음.
- [x] 정적 검토·변경 목록 정리. 서버 재시작·자동 재생 없음.

독립 정적 검토에서 설치된 VoiceStudio의 start 한 번→PCM→done 한 번 계약과의 충돌은
발견되지 않았다. 미로드/다른 모델 거절, 재생 완료 대기, 브라우저 연결 종료에 대한
합성 검사도 작성했다. 초기에는 미실행이었으며, 후속 실행 결과는 문서 마지막에 기록한다.

## 연결된 코드의 사용·수명

백엔드 재시작 후 응답이 화면에 있으면 하단에서 프로필을 선택하고 **응답 읽기**를 누른다.
읽기 전에 VoiceStudio 0.5.7의 이미 로드된 OmniVoice와 저장된 한국어 프로필을 확인한다.
미로드 상태에서 NERVIS가 모델을 내려받거나 임의로 로딩/설정을 변경하지 않는다.
응답의 Markdown 표시 기호·코드 블록·링크 주소를 제외한 텍스트만 전달한다.
2000자 초과 응답은 잘라 읽지 않고 명시 오류를 표시한다. 원래 응답/초안은 유지한다.

NERVIS 중계는 `WS /api/tts/stream` → 고정 `ws://127.0.0.1:3900/ws/tts`뿐이다.
브라우저가 외부 서버 주소·임의 엔진·파일 경로를 지정할 수 없다. 환경 프록시도 사용하지 않는다.
프로필 이름은 서버의 고정 ID 목록으로 해석하고 `language=Korean`, `engine=omnivoice`로 요청한다.
타이밍 메타데이터·원음·응답을 파일/로그/DB에 저장하지 않는다.
PCM은 mono s16le, 8~48kHz, 최대180초, 전체 중계/재생은 최대300초로 제한한다.

브라우저는 받은 조각을 즉시 오디오 버퍼로 예약한다(기본60ms 여유). `done`은 생성 완료이며
재생 완료와 구분한다. 마지막 오디오가 끝난 뒤 브라우저가 playback.finished를 보내야
서버의 STT/TTS 공통 잠금도 풀린다. 읽는 중 STT/새 요청/화면 전환을 막는다.
STT는 TTS 종료 후 자동 재시작하지 않으며 사용자가 명시적으로 켠다.
중지·탭 숨김·페이지 종료는 소켓/예약된 음원/AudioContext/음량 측정 프레임을 해제한다.
VoiceStudio 안에서 이미 시작된 문장 계산까지 즉시 중단되는 것은 보장하지 못한다.
빠른 중지/재시작·장시간 음성·TTS/STT의 실제 GPU 메모리 경합은 후속 검증 대상이다.

초기 코드 연결 때는 서버 재시작도 보류했다. 후속 검증에서는 TTS 코드로 재시작했고,
서버 프로세스의 AI 비활성/예산0을 유지했다. 환경 파일은 변경하지 않았다.

## TTS 스트리밍의 실제 범위

설치된 VoiceStudio 0.5.7의 `api/routers/tts_stream.py`를 읽었다.
`split_stream_sentences` → 문장마다 `backend.generate` → `start` 메타데이터 →
PCM16 mono 4800샘플 단위 binary → 모든 문장 후 `done` 순서다.
기본 프로필 JARVIS와 활성 엔진 omnivoice / k2-fsa/OmniVoice는 읽기 API로 확인했다.

즉 **문장 단위 생성 + PCM 조각 전송/재생**은 가능하다. 24kHz일 때 4800샘플은 200ms지만,
이는 오디오 조각 길이이며 첫 소리가 200ms 안에 나온다는 뜻이 아니다.
첫 문장의 전체 생성 시간은 먼저 필요하다. 앞 문장 재생 중 뒤 문장 생성은 가능하지만,
생성이 재생보다 느리면 문장 사이 공백은 생길 수 있다. 첫 소리/총 소요 시간은 아직 미측정이다.

현재 AI 경로도 완성된 JSON 답변을 반환하므로 LLM 토큰→첫 문장→TTS까지 이어지는
전체 스트리밍은 이번 범위가 아니다. 이를 하려면 AI 응답 계약·검증·도구 사실 확인 시점도
함께 바꿔야 한다. 확인되지 않은 계산 결과를 먼저 말하지 않도록 별도 설계가 필요하다.

## STT의 현재 상태와 가능한 개선

현재 NERVIS는 16kHz에서 약8ms짜리 PCM 프레임을 연속 전송하며, 1초 이상 모은 뒤
대략1초 간격(추론 완료 후 기준)으로 부분 인식한다. 0.8초 무음 또는 발화15초에서 확정한다.
발화가 끝날 때까지 아무것도 하지 않는 구조가 아니다. 다만 Whisper는 기본적으로
녹음 구간을 반복 전사하는 모델이므로 이 부분 인식은 모델 내부의 진짜 토큰 스트리밍과 다르다.

문맥 손실·재인식·단어 잘림·GPU 호출 증가를 일으킬 수 있어 작을수록 항상 낫지는 않다.

### 1.15배속과 말하기 상태 구분 — 수정, 미검증

응답 전체 PCM을 로컬 WAV Blob으로 포장해 HTMLAudioElement의 playbackRate=1.15,
preservesPitch=true로 재생한다. Schedar 목소리의 음높이를 유지하며 재생 시간만 줄이는 방식이다.

명시적 중지/페이지 종료 시 미디어 이벤트·재생·로컬 Blob URL·노드·컨텍스트를 정리한다.
속도는 현재 프런트 기본값 1.15이며 별도의 화면 설정이나 환경 변수는 추가하지 않았다.
SPEAKING은 보라색 상태 칩·점·코어 색으로 구분한다. 기존 대기 파랑·처리 주황·분석 민트와 다르다.
합성 테스트 내용도 새 재생 경로에 맞춰 수정했지만 사용자 요청에 따라 실행하지 않았다.
실제 브라우저 음높이·재생 속도·백그라운드 유지와 빌드는 미검증이며 유료 호출/커밋은 하지 않았다.

### 목소리 Schedar 변경 — 최신 설정

기본 목소리도 Schedar로 바꿨다. 모델은 gemini-3.1-flash-tts-preview, STT는 기존 로컬 설정을 유지한다.
이후 목소리는 `.env`의 NERVIS_TTS_VOICE만 변경하면 된다(OS 환경에 같은 값이 있으면 OS 우선).
설정을 읽는 시점에 반영되지만, 프런트/백엔드 버전 차이를 피하려면 서버 재시작 후 새 요청으로 확인한다.

### HAI GPT Umbriel·백그라운드 재생 — 최신 수정 기준, 미검증

사용자 요청으로 STT는 기존 로컬 한국어 Turbo GPU를 유지하고 TTS만 HAI GPT로 전환했다.
실제 `.env`와 `.env.example`의 TTS 관련 세 항목만 설정했다:
`NERVIS_TTS_BACKEND=hai_gpt`, `NERVIS_TTS_MODEL=gemini-3.1-flash-tts-preview`, `NERVIS_TTS_VOICE=Umbriel`.
기존 BAZE_API_KEY, AI 활성/예산 설정, VoiceStudio 저장 프로필과 STT 설정은 변경하지 않았다.
OS 환경 변수가 같은 이름으로 설정되어 있으면 기존 규칙대로 파일보다 우선한다.

backend/hai_tts.py 어댑터는 고정된 HAI Gateway `/audio/speech/`에 model/input/voice만 전송한다.
키는 서버에서만 읽고 브라우저·로그·문서로 보내지 않는다. 원본 파일·이미지·마스크·전체 시계열·경로는
이 요청에 포함하지 않으며 기존에 허용된 응답 요약만 읽는다. PCM16 LE/24kHz/모노 응답을 기존 로컬
WebSocket PCM 규약으로 전달하고, 프런트는 전체 수신 후 한 번에 재생한다. 자동 재시도·다른 모델로의
자동 전환·설치·다운로드는 없다. TTS용 모델 목록·크레딧·가격·건강 상태 API 조회도 시작 시 실행하지 않는다.

형식 검사일 뿐 인증·모델 권한·실제 가용성의 확인이 아니다. 오류는 인증/크레딧/권한/호출 한도/오디오 형식으로
구분해 표시한다. 요청 중 중지해도 이미 시작된 외부 생성의 과금 취소를 보장하지 않으며 자동 재전송하지 않는다.

탭 숨김은 요청 취소·소유권 해제·음성 중지의 이유로 사용하지 않는다. 숨겨진 상태에서 도착한 결과도 음성을
준비하고 재생할 수 있다. WebGL 프레임이 숨겨진 탭에서 멈춰 화면 준비가 대기 중이면 음성은 독립적으로
시작하고, 복귀 후 무대를 준비해 표시한다. 복귀가 같은 음성을 처음부터 다시 재생하는 계기가 되지 않는다.
3D·시계열의 보이지 않는 그리기는 줄이고, 복귀 시 자동 샘플 재생은 현재 커서에서 이어간다.
실제 페이지 종료/새로고침/새 대화·명시적 중지의 자원 정리와 오래된 요청 차단은 유지한다.
브라우저의 탭 폐기·OS 절전이나 사이트 소리 차단까지 백그라운드 재생을 보장하는 변경은 아니다.

### AI 설명 형식 실패 후속 처리 — 수정, 미검증

기존 설명 요청에 Gateway Responses의 `text.format` JSON schema를 명시한다. answer/used_fact_ids 두 필드만
허용하고 사용 가능한 근거 ID를 enum과 지시문에 지정한다. 서버의 필드·근거 검증은 유지하며 추가 모델 요청이나
자동 재시도는 하지 않는다. 공식 문서의 text 파라미터 지원을 근거로 작성했고 현재 실계정 호환성은 시험하지 않았다.
참고: https://docs.mindlogic.ai/docs/hallym-ac/api-gateway/reference/responses-api

설명이 거절되면 기존 invalid_grounded_explanation 코드와 함께 explanation_error에 invalid_json,
invalid_fields, empty_answer, missing_fact_ids, duplicate_fact_ids, unknown_fact_ids를 구분해 저장한다.
Gateway 실패는 기존 오류 코드로 구분한다. 서버 로그에는 사유 코드만 남기고 거절된 원문·개인 내용은 저장하지 않는다.
이 메타데이터는 기존 대화 reply 저장 경로를 사용하므로 DB 스키마 변경은 없다. 과거 실패 원문은 복구할 수 없다.

backend/response_text.py가 실제 결과의 선택 필드로 길이를 제한한 기본 안내를 만든다. 브리핑의 날짜/수업,
서버가 분류한 할 일 그룹/상태/기한과 관측 기온만 사용한다. 조회 실패를 빈 일정으로 말하지 않고, 생략·추가 항목은
화면을 안내한다. 분석 실패 시 수치나 해석을 만들어내지 않고 실제 결과 화면을 안내한다.
응답은 partial/warning을 유지하고 explanation_source=local_results로 기본 안내임을 표시한다.
프런트는 이 경우 전체 시스템 ERROR 대신 결과를 표시·낭독하고 설명 오류 정보에서 진단 코드를 보여준다.
실제 도구 실행 실패나 화면 준비 실패의 오류 처리는 유지한다.

사용자 요청으로 코드와 합성 테스트 내용만 수정했으며 테스트·빌드·유료 AI·실제 TTS·브라우저 검증과 커밋은
하지 않았다. 백엔드 재시작 후 새 요청으로 확인한다. 기존 실패 요청의 저장된 결과는 소급 변경하지 않는다.

### 전체 음성 준비 후 재생으로 변경 — 최신 기준

사용자가 문장 사이의 긴 무음보다 첫 대기를 허용하는 방향을 선택했다. 이 절이 아래 구간별 생성·즉시 재생
기준보다 우선한다. 현재는 로컬 VoiceStudio를 유지하며 HAI GPT 연결/실계정 요청은 하지 않는다.

- 답변 전체 텍스트를 한 번의 TTS 요청으로 보낸다. 프런트가 문장별 합성 요청을 만들지 않는다.
  VoiceStudio 내부에서 문장별로 생성하더라도 모든 PCM과 done을 받은 후 하나의 AudioBuffer로 연결해
  재생한다. 최대 2000자/180초의 기존 제한과 취소/소유권/자원 정리는 유지한다. 생성 과정 때문에
  발생하던 중간 대기를 재생 이전으로 옮기는 변경이며, 모델 자체의 문장 사이 무음을 편집하지는 않는다.
- 음성 준비와 재생 시작을 분리한다(preparing → ready → speaking). 음성 준비에 걸린 시간을 ready 상태에
  표시한다. 전체 생성 실패 시 일부만 재생하지 않고 텍스트 결과와 오류를 남긴다.
- 분석 요청은 기존 화면을 유지하면서 분석 데이터·MRI·3D를 보이지 않는 별도 무대에서 준비한다.
  음성과 3D/분석 화면이 모두 준비되면 그 무대를 표시하고, DOM 반영 뒤 전체 음성 재생을 시작한다.
  준비 중 취소/탭 숨김은 대기 음성과 보이지 않는 준비 무대를 폐기한다. 실패 시 이전 화면을 유지한다.
- 음성 재생 여부를 분석 화면의 blocked/inert 조건에서 분리한다. 3D 조작과 시계열 샘플 재생은 음성을
  읽는 중에도 가능하며, 준비 무대의 시계열은 표시할 때 시작한다. 새 명령 입력은 여전히 응답 처리 중 잠근다.
- 브리핑은 전체 음성 재생 시작에 맞춰 카드 전체를 표시한다. 문장/항목별 정확한 강조는 이번 방식에서
  사용하지 않는다. AI 설명 요청도 answer/used_fact_ids만 요구하고 출력 상한을 다시 1200토큰으로 둔다.
  이전 segments 필드는 호환용으로 읽을 수 있지만 음성 요청 분할이나 추정 타이머에 사용하지 않는다.

이번 변경도 사용자 요청에 따라 수정만 수행했다. 테스트 코드는 전체 버퍼/준비 대기 기준으로 수정했지만
실행하지 않았다. 테스트·빌드·실제 음성 생성·브라우저 확인·서버 재시작·커밋은 하지 않았다.
수동 확인: 백엔드 재시작/브라우저 새로고침 → 더미 응답 전체 준비 후 연속 재생 확인 → 실제 분석 요청 시
기존 화면에서 대기하다 분석 화면과 낭독이 함께 시작하는지 확인 → 재생 중 3D 조작/시계열 이동 확인 →
준비 중/재생 중 중지 확인. 냉간 로딩 및 전체 생성 대기는 길 수 있으며 HAI GPT 전환은 이후 별도 결정한다.

  SQL·경로·인수·원시 결과를 진행 이벤트에 넣지 않는다. 최종 결과는 기존 저장 트랜잭션이 끝난 뒤 전달한다.
  기존 JSON `POST /api/ai/chat`도 유지한다. 모델 토큰 스트리밍이나 추가 모델 호출을 만드는 변경은 아니다.
- 프런트 `chatStream.ts`는 자동 재연결/재전송 없이 이벤트를 읽고 두 소유권 ID를 검사한다. 도구 종류에 따라
  실제 작업 진행 문구를 표시하며 기존 결과 종류별 화면 선택과 오디오 시계 기반 카드/행 연결은 재사용한다.
- 같은 요청/세션 ID를 TTS 요청·메타데이터·재생 완료 확인에도 연결한다. 플레이어의 세대 번호와 함께
  늦게 도착한 응답/오디오/카드 및 분석 완료 알림을 현재 요청으로 오인하지 않게 처리한다.
  음성 중지 시 예약 음성과 강조를 해제하고 결과는 남긴다. 탭 숨김/종료와 대화 초기화는 소유권을 폐기한다.
- 연결이 끊겨도 서버에서 시작된 도구/DB 쓰기를 강제로 취소하거나 자동 재실행하지 않는다. 서버 작업은 기존
  트랜잭션과 요청 ID 저장 규칙에 따라 마무리되며, 사용자는 대화 기록에서 결과를 확인한다. 서버 종료는 남은
  작업을 기다린 뒤 상태를 정리한다. 음성 중지는 이미 완료된 할 일/수업 변경을 되돌리는 기능이 아니다.
- `backend/speech_engine.py`의 `SpeechEngine` 규약과 `VoiceStudioEngine` 구현으로 로컬 HTTP/음성 연결,
  프로필·모델 상태 확인, 예열, 합성 요청을 분리했다. 현재 어댑터 한 개를 재사용하며 기존 예열·잠금·PCM
  형식/길이 제한은 유지한다. 다른 엔진을 추가하려면 같은 메타데이터/PCM 규약으로 변환하는 어댑터를 구현한다.
  자동 엔진 탐색·외부 서비스 전환·새 환경 변수는 넣지 않는다.

이번 후속 변경은 사용자 요청으로 수정만 수행했다. 테스트·타입 검사·빌드·실제 HTTP·AI·음성·브라우저
검증을 실행하지 않았고 서버도 재시작하지 않았다. 아래 이전 검증 수치를 이 변경의 통과 기록으로 취급하지 않는다.
문장 사이 무음 개선용 버퍼 정책과 생성 엔진 성능은 이번 수정 대상이 아니다.

사용자 확인 순서: 백엔드 재시작 → 브라우저 새로고침 → 더미 미리보기에서 카드/음성 및 중지 확인 →
더미를 끄고 실제 요청에서 작업 진행 문구/최종 결과/낭독 확인 → 재생 중 탭 숨김 후 복귀 시 음성이
되살아나지 않는지 확인 → 새 대화에서 이전 카드 강조가 이어지지 않는지 확인. 실제 요청 중 탭을 숨겼다면
같은 명령을 바로 다시 보내기보다 대화 기록을 확인한다. 새 SSE 경로는 백엔드 재시작 전에는 사용할 수 없다.

기존 설명 요청이 `answer`, `used_fact_ids`와 함께 선택적인 `segments: [{text, target}]`를 반환한다.
별도 모델 요청은 추가하지 않는다. 구조화 출력 때문에 설명 응답의 최대 출력은 1200에서 2000토큰으로 늘었으며,
실제 사용 토큰과 비용은 달라질 수 있다. 개발 검증은 모의 Gateway만 사용한다.

구간은 최대 12개, 전체 음성 문장은 2000자 이하다. 구간을 합친 내용이 답변과 같고 현재 표시할 수 있는
결과의 대상만 참조해야 한다. `response`, `rN.weather`, `rN.classes`, `rN.tasks`와 항목별 `.0`, `.1` 등의
위치 키를 사용한다. DB 식별자나 원본 데이터를 연결 정보에 추가하지 않는다. 서버와 프런트가 모두 검증한다.
잘못된 연결 정보나 구간별 서식 정리 불일치는 연결 정보만 버리고 일반 낭독으로 처리한다.

VoiceStudio의 같은 로컬 WebSocket에서 구간별 생성을 이어가며 다음 구간 생성과 현재 구간 재생을 겹친다.
첫 PCM의 예약 재생 시각을 AudioContext 시계로 확인할 때만 구간 대상을 활성화한다. 생성 완료나 수신 시점은
카드 전환 기준이 아니다. 버퍼가 비면 현재 구간을 유지한다. 종료·오류·중지·탭 숨김은 예약 음성과 구간을 취소한다.

브리핑 카드는 음성에서 실제로 등장한 순서에 따라 나타나고 해당 수업/할 일 행을 강조한다. 다 읽거나 중지/실패하면
모든 결과를 오른쪽에 정리한다. 마지막 0.9초는 CSS 이동 완료 대기이며 음성 길이를 추정하는 타이머가 아니다.
연결 정보가 없으면 결과를 바로 정리해 보여준다. 움직임 축소 설정에서는 카드 이동을 생략한다.
현재 화면 대상은 선택된 브리핑과 할 일 영수증이다. 중복 조회의 표시하지 않는 결과, 완료되어 숨겨진 브리핑 항목,
분석 화면이 우선되는 혼합 결과에는 해당 카드 키를 허용하지 않는다. 새 기능은 대상 목록과 화면 처리기를 함께 추가한다.
임의의 새 도구/화면이 자동으로 동기화되는 것은 아니다. 단어별 타임스탬프 정렬은 구현하지 않는다.

말하는 코어는 실제 출력 음량의 빠른 상승/느린 감쇠를 이용해 핵 크기·밝기, 링 기울기, 입자 크기를 조절한다.
주파수 대역 분석을 추가하지 않았으며 움직임 축소 시에는 음량에 따른 변형을 생략한다.

수동 확인: 백엔드를 재시작하고 브라우저를 새로고침한다. 더미 미리보기에서 “오늘 할 일 알려줘”를 보내고
날씨/수업/할 일 낭독 시점과 카드/행 강조, 마지막 오른쪽 정리, 음성 중지 후 입력 재개를 확인한다.
이어서 더미를 끄고 실제 요청을 사용자가 전송한다. 문장이 달라도 같은 연결 계약을 사용한다.
생성 지연, 구간 경계의 억양/공백, 모델의 대상 선택 품질은 실제 청취로 확인해야 한다.
