# NERVIS 음성 상호작용·영상 제작 시나리오

기준: 2026-10-22. 현재 기획의 촬영·연출 설계다. 타이틀·다층 코어·버튼 기반 실제 데이터 탐색 화면은 구현했다. 코어 조형·음량 반응과 공통 입력 구조를 추가 구현했다. 초기 미연결 정보 카드는 후속 피드백에 따라 제거했다. 실제 음성 상호작용·브리핑·고급 장면·본편은 아직 제작하지 않았다. [전체 기획](PROJECT_DIRECTION.md), [시스템 규격](SYSTEM_ARCHITECTURE.md)

## 1. 영상이 전달할 경험

사용자가 NERVIS를 호출하고, 눈앞의 뇌 데이터에 질문하고, 시스템이 실제 분석·화면 조작으로 응답한다. 관객은 같은 자료에서 관계를 발견하고 질문을 바꾸면 다른 모습을 볼 수 있음을 경험한다. 마지막에는 발견한 관계를 빛과 움직임으로 확장한다.

작품의 정체성은 음성 탐색과 데이터의 예술적 표현을 연결하는 데 있다. 분석 수치를 길게 읽는 설명 영상이나 200점을 재생하는 화면만으로 구성하지 않는다. 제공된 단면의 윤곽·라벨 형태를 작품의 시각적 출발점으로 사용한다.

## 2. 약 3분 편집 구성

시간은 목표 편집 길이다. API·STT의 실제 지연을 촬영하기 전에 보장한 수치가 아니다. 발화와 화면 이해에 시간이 더 필요하면 컷 수를 줄인다.

최신 흐름은 도입 약30~40초에 “오늘 해야 되는 거 알려줘”→실제 조회한 춘천 날씨·등록한 수업·뇌 분석 과제를 브리핑하고 카드들을 오른쪽 위에 정리하는 장면을 넣는 것이다. 이어 “뇌 데이터 분석 과제부터 시작하자”로 아래 분석 장면을 시작한다. 약3분 목표를 유지하기 위해 분석 장면의 질문·길이를 선별하며 아래 시간표는 브리핑 추가 전의 구성 참고다. 후속 질문은 각 요청의 도구 실행·초기 화면 전개·응답 음성이 끝난 뒤에만 한다. 처리 중 끼어드는 대사는 넣지 않는다. 분석에서 코어는 왼쪽 위에 충분히 크게 남아 실제 발화에 반응하고, 입력창은 T·마이크로 접는다. 기준은 [프런트 설계 8절](FRONTEND_DESIGN.md#8-다음-구현의-합의된-화면상호작용)이다. 이 흐름의 실제 대화·음성·브리핑 기능은 아직 미구현이다.

| 구간 | 사용자 발화 예시 | 실제 시스템 동작 | 영상·음향 의도 |
|---|---|---|---|
| 0:00~0:10 | 없음 | 중앙 NERVIS 타이틀이 왼쪽 위로 이동한 뒤 푸른 다층 코어 등장·대기 | 코어는 주황색 레퍼런스의 겹친 궤도·분절 구조를 푸른 계열로 표현. 타이틀은 왼쪽 위에 유지 |
| 0:10~0:25 | “NERVIS.” | 호출어 인식, 코어 활성화, 짧은 응답 | 실제 재생 음성에 코어가 반응하며 시스템과 첫 대면 |
| 0:25~0:50 | “가장 비슷하게 변하는 두 영역 찾아줘.” | 20 ROI 전체 구간의 쌍별 유사도 계산·순위·선택 | 여러 파형에서 두 영역으로 시선이 모임 |
| 0:50~1:10 | “둘만 따로 보여줘. 원래 어디인지도.” | 선택 ROI 확대, 주변 흐리기, 원래 단면 위치와 비교 패널 | “둘”의 맥락을 이해하고 실제 영역을 선택하는 장면 |
| 1:10~1:40 | “처음부터 끝까지 계속 비슷해?” | 현재 두 ROI의 창별 유사도 계산, 구간 강조 | 하나의 숫자에서 시간에 따른 관찰로 확장 |
| 1:40~2:10 | “그럼 좌우가 덜 비슷한 영역은?” | 좌우 대응 10쌍 검색, 현재 기준에 맞는 쌍 선택·비교 | 앞 장면과 다른 관계가 나타나는 대비 |
| 2:10~2:35 | “이 구간만 다시 보여줘.” 또는 “아까 둘로 돌아가줘.” | 실제 선택 구간 재생 또는 이전 상태 복원 | 후속 질문이 화면·그래프·밝기를 함께 바꿈 |
| 2:35~2:50 | “이 관계를 빛으로 표현해줘.” | 선택·구간의 값을 정의된 예술 매핑에 적용 | 형태는 유지하고 변화·관계가 빛·점·선으로 번짐 |
| 2:50~3:00 | 짧은 마무리 | 데이터·AI·창작 규칙 크레딧 | 관객에게 작품의 근거와 제작 방식을 간결하게 남김 |

예시 발화는 촬영 순서 제안이다. 문장 문자열로 장면을 고르는 구현 규칙이 아니다. 실제 응답은 해당 호출의 결과를 근거로 짧게 생성한다. 최종 영상에는 모든 질문을 넣기보다 흐름이 가장 잘 이어지는 실제 테이크를 선택한다.

시작 때 중앙 NERVIS 타이틀이 왼쪽 위로 이동하고, 이후 홈에서는 다층 구형 코어만 중앙의 주 대상으로 둔다. 첫 분석 요청 시 코어가 가장자리로 이동하면서 실제 뇌 단면·영역 패널이 열린다. NERVIS 글자는 왼쪽 위에 유지한다. 분석 화면에서도 작은 코어가 실제 응답 오디오에 반응한다. 코어는 시스템의 시각적 정체성이며 뇌 소유자의 인격·의식을 재현하는 표현이 아니다. 초기 개발의 버튼·미리보기 음원 시험은 실제 호출어·AI·TTS 동작으로 촬영하지 않는다. 상세 화면·모션 기준은 [FRONTEND_DESIGN.md](FRONTEND_DESIGN.md)를 따른다.

## 3. 분석 장면의 근거와 관찰점

### 3.1 비슷한 두 영역 찾기

기존 탐색 분석에서는 전체 200점 Pearson 기준 왼쪽·오른쪽 대상피질이 가장 높은 유사성을 보였다. 앱은 이 이름·ID를 답으로 고정하지 않고 같은 조건에서 순위를 계산한다. 대상·구간·방법이 바뀌면 그 조건으로 검색한다. [분석 근거](DATA_ANALYSIS_RESULTS.md)

이 장면은 “멀리 떨어져 보이는 영역의 평균 신호가 함께 변할 수 있다”는 관찰을 전달한다. 두 영역 사이의 선은 유사성 표시이며 실제 섬유를 추출한 선이 아니다.

### 3.2 둘만 꺼내 보여주기

“둘”은 직전에 선택된 두 ROI다. 왼쪽·오른쪽 반구 전체를 뜻하지 않는다. 실제 Labels에서 두 ID의 픽셀을 선택하고, 해당 단면의 원래 위치를 남긴 채 확대된 패널로 보여준다. 각 영역에서 같은 ID의 파형을 연결한다.

영역이 한 장에서 잘 안 보이면 기존 공간 분석의 노출 정보를 사용해 적합한 단면을 고른다. 이 이동은 단면 선택이지 공간에서 뇌 조직을 잘라낸 행위가 아니다.

### 3.3 계속 비슷한가 묻기

창별 비교를 통해 전체 구간의 높은 r이 각 부분에서도 유지되는지 보여준다. 창 길이와 표시 구간은 화면에서 확인할 수 있어야 한다. 높은 유사성이 유지되더라도 “완전히 같다”, “직접 정보를 주고받는다”라고 설명하지 않는다.

### 3.4 덜 비슷한 좌우 쌍 찾기

여기서는 검색 범위를 전체 190쌍에서 좌우 대응 10쌍으로 바꾼다. 기본 기준은 전체 구간 r의 오름차순이다. 기존 분석에서는 후두정피질 대응 쌍이 이 집합에서 낮았고, 창별 값의 변화도 관찰되었다. 장면에서는 현재 설정으로 다시 확인한다.

낮은 유사성을 기능 이상·좌우 불균형·질환으로 해석하지 않는다. 같은 자료를 보는 질문과 구간이 달라지면 발견하는 특성이 달라진다는 대비를 만든다.

### 3.5 빛으로 전환하기

단면·ROI 형태는 고정한다. 커서에 따른 상대 변화는 밝기에, 계산한 유사성은 선택한 쌍의 선 강도에 연결한다. 부드러운 입자·잔광은 창작 규칙이다. 실제 조직 팽창이나 ROI 내부의 신경 활동 전파처럼 설명하지 않는다.

데이터 화면에서 예술 장면으로 전환할 때 같은 선택 색·위치·리듬을 유지해 연속성을 만든다. Google 생성 배경을 쓰더라도 ROI·그래프·수치는 로컬 렌더 결과를 합성한다.

### 3.6 발견한 특징을 관객이 이해하게 하기

2026-10-21 사용자 요청: 데이터에서 관찰한 안정적인 좌우 유사성과 구간에 따라 달라지는 관계가 본편에 드러나야 한다. 기존 3.1~3.4 장면의 설명·그래프에 반영하며 별도 장면을 늘리거나 개인의 능력·성격을 판정하지 않는다.

| 기존 장면 | 전달할 관찰 | 화면과 설명의 연결 |
|---|---|---|
| 비슷한 두 영역 → 계속 비슷한가 | 선택 조건에서 닮은 파형과, 여러 창에서도 유지되는 정도 | 두 파형과 창별 결과를 같이 표시. 결과가 뒷받침하는 경우에만 “선택한 창들에서도 비슷한 변화가 유지됩니다”라고 설명 |
| 덜 비슷한 좌우 쌍 → 이 구간만 | 전체 요약과 부분 구간의 관계가 다를 수 있음 | 전체 값과 선택 구간·창별 값을 구분. 실제로 확인된 변화의 방향과 범위만 설명 |
| 빛으로 전환 | 함께 움직이는 흐름과 서로 다른 흐름의 대비 | 같은 결과의 상대 변화·유사성을 밝기·선 강도에 연결. 분석 화면에서 사용한 영역과 구간을 유지 |

위 문장은 응답 의도의 예시이며 고정 음성 답변이나 판정 규칙이 아니다. 실제 선택·구간·방법과 실행 결과를 근거로 설명한다. 높은 유사성을 집중력·학습량·지능으로, 낮거나 변하는 유사성을 성격·기능 이상으로 바꾸어 말하지 않는다. 인지 특성을 물으면 이 자료만으로 판단할 수 없다고 답한다. 상세 수치를 포함한 설명의 외부 전송·음성 처리에는 시스템 문서의 로컬 처리 규칙을 적용한다.

이 흐름에 필요한 조회·검색·두 영역 비교·이동 창·단면 선택의 로컬 함수는 구현했다. 첫 화면은 시작 타이틀→왼쪽 위 이동→푸른 다층 코어, 버튼→코어 축소→실제 MRI·마스크·좌우 파형 비교까지 연결했다. 초기 코어 반응은 명시된 로컬 합성음 미리보기이며 음성 대화·호출어·세션 연결의 증거가 아니다. 최신 프런트에서는 대응 쌍의 로컬 상관 검색·자동 선택, 실제 단면 기반 입자 무대·양쪽 ROI 확대·관계선·창별 상관·선택 구간 재생을 구현했다. 이는 명시된 미리보기로 실행하며 자연어로 이 장면들을 호출하는 기능, 임의 두 영역 선택·예술 모드는 후속 작업이다. 깊이·관계선·재생 속도는 연출이고 물리적 3D 복원·직접 신경 연결·실제 촬영 시간으로 설명하지 않는다. PCA·스펙트럼·주요 시점 분석은 탐색 결과가 있지만 대화형 함수가 없으며, 위 핵심 흐름의 선행 조건으로 추가하지 않는다. 필요한 장면이 확정될 때 별도 확장한다.

## 4. 화면과 말투

- 기본 화면은 중앙의 실제 단면·ROI, 비교 때 나타나는 파형·지표, 아래의 시간점·발화 자막으로 구성한다.
- 호출 전은 절제된 대기 상태, 호출 후에는 형태와 선택이 단계적으로 드러난다. 모든 패널이 한꺼번에 깜박이는 연출을 피하고 질문의 대상이 시선의 중심이 되게 한다.
- 어두운 바탕과 제한된 강조색을 사용하고, 영역 구분은 제공 팔레트·이름·선 스타일을 함께 쓴다. 청록 계열 분위기와 데이터 색의 역할을 구분한다.
- AI는 한 번에 핵심 1~2문장으로 답한다. 사용자에게 필요한 경우에만 지표 이름·구간·한계를 말하고, 수식·내부 API 이름을 음성에 넣지 않는다.
- 상관계수는 “유사도 95.3퍼센트”로 바꾸지 않는다. 필요하면 “상관계수 약 0.95”처럼 읽고 원 수치는 화면에 표시한다.
- 촬영 중에는 모델명·키·개발 로그를 UI 중앙에 노출하지 않는다. 구현 증거는 실제 상호작용과 별도의 로컬 기록으로 보관한다.

## 5. 실제 시스템임을 확인하는 촬영

1. 데이터가 로딩된 실제 앱에서 호출→질문→계산→화면 변경→후속 질문을 연속 실행한다.
2. 준비 문장 외에 같은 뜻의 표현, 다른 ROI·구간, 순서 변경을 시험한다. 이 시험도 개발 기록으로 남긴다.
3. 최소 한 구간은 중간 컷 없이 호출과 후속 질문이 이어지는 테이크로 확보한다.
4. 세션 로그의 발화·도구·인자·결과 ID·화면 버전과 촬영 시각을 연결한다. 상세 로그는 비공개로 둔다.
5. 편집본에서 긴 대기나 반복을 줄일 수 있으나, 발화와 다른 계산·화면을 붙여 실제 동작처럼 보이게 하지 않는다.

네트워크 장애 테이크는 실패로 남긴다. 재생 영상이나 사전 녹음 응답으로 대체하면 해당 장면은 재현·연출임을 구분한다. 통계 계산이 고정 데이터에서 반복되는 것과 질문·답을 고정해 재생하는 것은 다르다.

## 6. 촬영·편집 절차

| 단계 | 작업 | 산출물 |
|---|---|---|
| 리허설 | 실제 마이크·헤드폰·출력 음량, 한국어 인식·TTS, 화면 성능 시험 | 채택할 실행 경로·발화·목소리 |
| 캡처 준비 | OBS 화면·마이크·앱 음성 소스 확인, 알림·개인 화면 제외 | 10~20초 시험 녹화·전체 재생 확인 |
| 본 촬영 | 핵심 연속 테이크와 장면별 보충 촬영 | `reports/production/capture/` |
| 소재 제작 | 직접 만든 그래픽·효과음, 선택 Google 생성 소재 | `reports/production/media/`와 출처 기록 |
| 편집 | 컷·전환·자막·음량·필요한 크롭, 실제 녹화와 소재 합성 | `reports/production/edit/` |
| 출력 | PyAV로 H.264/AAC MP4, 목표 1080p 30fps·오디오 48kHz | `reports/production/final/NERVIS.mp4` |
| 검수 | 전체 재생·디코딩·오디오 동기화·글자 가독성·용량 확인 | 최종 점검 기록 |

OBS는 앞으로 설치·시험할 촬영 도구다. 현재 별도 FFmpeg CLI·상용 편집기가 있는 것으로 가정하지 않는다. PyAV를 통한 짧은 합성 MP4 시험은 가능했지만 본편 편집 품질·긴 렌더 성능은 별도 확인한다. [OBS 촬영 안내](https://obsproject.com/kb/quick-start-guide), [PyAV](https://pyav.org/docs/stable/)

음성·음악·효과음은 레벨을 맞추고 대사가 묻히지 않게 한다. 사용자 발화와 앱 음성을 가능하면 분리해 보관한다. 시스템 음성이 마이크로 다시 들어가 명령이 되는 현상은 녹화 전 차단한다. 설치된 도구나 브라우저에 따라 사용자에게 녹화 대상 선택·권한 허용이 필요하다.

## 7. AI 활용 보고서와 제출 파일

보고서는 공고의 A4 2쪽 이내 조건에 맞춰 다음 내용을 압축한다.

- 작품 의도와 실제 시스템→녹화 영상의 제작 방식.
- 제공 자료에서 사용한 구조·시계열·ROI 마스크, 대표 분석과 표현의 관계.
- 실제 사용한 BAZE 모델 ID·도구 호출·STT·TTS, 개발 보조 AI와 역할.
- Google 생성 영상이 있으면 실제 모델·프롬프트 예시·채택 및 수정 과정·사용 장면.
- 수치 분석, 생성 결과, 창작 매핑, 단면 기반 입체 연출의 구분과 해석 한계.

예정 도구를 사용한 도구로 적지 않는다. 교수님의 승인 이메일을 기술 검증이나 데이터 재배포 허가로 확대 해석하지 않는다. 최종 제출은 MP4·AI 활용 보고서 PDF와 접수 화면이 요구하는 항목을 따른다. 대표 이미지는 요구되거나 필요할 때 본편에서 추출하며 별도 필수 제출물로 단정하지 않는다.

최종 파일·상세 촬영본·대화 로그는 `reports/` 아래 로컬에 둔다. 공모전 파일 제출과 GitHub 공개·외부 생성 서비스 입력은 서로 다른 사용 범위다.
